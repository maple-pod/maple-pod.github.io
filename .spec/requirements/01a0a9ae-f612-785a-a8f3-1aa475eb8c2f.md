## Contract
Maple Pod must expose All, Liked, and custom playlists as distinct product concepts. All must represent the available music catalog and must not allow user membership mutation. Liked and custom playlists must persist as saveable collections.

The user must be able to add music to and remove music from Liked and custom playlists, and those membership changes must persist. Custom playlists must preserve an explicit member order and allow the user to change that order. A reorder operation must not remove any playlist member unless the user separately performs a membership-removal action; presenting or reordering only a filtered/partial subset must not implicitly delete unpresented members.

Custom playlist titles must be validated after trimming, must not be empty, and must not exceed 50 characters. Each custom playlist must have a stable opaque identity sufficient for persistence and lookup; the identity encoding, prefix, and generation algorithm are not part of this contract.

Deleting a custom playlist must require explicit user confirmation before the deletion is applied. Declining or cancelling confirmation must leave the playlist intact.

When saved playlist data references music that no longer resolves in the current catalog, Maple Pod must remove those stale references during readiness normalization so the resulting saveable playlist contains only resolvable music entries.

## Rationale
These rules define the product-level playlist model while leaving identity encoding and presentation technique outside the contract. The reorder contract deliberately preserves membership so a filtered presentation cannot accidentally redefine ordering as deletion. Stale-reference removal is a data-integrity guarantee rather than a one-off migration behavior.

## Verification
Verify that All, Liked, and custom playlists are exposed distinctly. Attempt to mutate All membership and confirm it is disallowed. Add and remove music from Liked and custom playlists and confirm persistence across reload. Create or rename custom playlists with blank, 50-character, and over-50-character titles. Reorder a full custom playlist and a filtered/partial presentation and confirm only order changes while all non-removed members remain present. Request custom-playlist deletion, cancel once to verify no deletion, then confirm once to verify deletion. Reload and confirm stable custom identity. Inject stale music references into saved playlist data and confirm readiness normalization removes them.
