## Contract
Maple Pod must make an About/context notice available to users and must proactively present it once on the first recorded visit for each browser/device. After the user dismisses that first-visit notice, Maple Pod must persist the dismissal locally so normal subsequent visits on the same browser/device do not automatically reopen it. The notice must remain manually accessible from Settings.

The first-visit/onboarding dismissal state is device/browser-local metadata. It must not be included in portable Saved Data. Normal Reset Saved Data must preserve it, while Factory Reset must clear it. External clearing of the relevant browser storage may likewise restore first-visit behavior.

The About/context notice must communicate the following semantics clearly:
- Maple Pod is a fan-made MapleStory BGM player;
- music metadata/source context, including the maintained source attribution in use at that time;
- intended personal listening / non-commercial use context;
- a usable contact path for copyright owners;
- non-affiliation with game development/operation organizations;
- the identity of the running Maple Pod build.

If build identity is displayed, it must correspond to the running build and must not knowingly present a different build identity.

The exact wording, paragraph structure, named organization examples, visual layout, local-storage key, and dialog mechanism are non-normative. The current English copy must not be treated as immutable legal text; wording may evolve while preserving the required semantic content and avoiding misleading claims.

## Rationale
The disclosure provides context that users should not need to infer from source code or project history. Proactive one-time presentation makes that context visible without repeatedly interrupting returning users. Keeping dismissal local rather than portable ensures each new browser/device receives the notice once, while Factory Reset restores truly fresh-device semantics.

## Verification
Use a fresh browser/device state and verify About opens proactively once. Dismiss, reload, and revisit to confirm it does not automatically reopen. Confirm manual Settings access still works. Perform normal Reset Saved Data and verify dismissal remains; perform Factory Reset and verify the next visit presents About again. Export/import portable Saved Data to another fresh browser/device and verify the imported data does not suppress the first-visit notice. Verify all six required semantic content categories are present and the displayed build identity matches the running build. Modify wording while preserving semantics and confirm no requirement depends on exact existing sentences.

## Reverse-spec evidence
Observed in `src/App.vue`, `src/components/AboutDialog.vue`, and `src/components/SettingsDropdownMenu.vue`. One-time proactive disclosure, local persistence until Factory Reset/storage clearing, all six semantic content categories, build-identity accuracy, and non-verbatim wording were explicitly accepted during product review.
