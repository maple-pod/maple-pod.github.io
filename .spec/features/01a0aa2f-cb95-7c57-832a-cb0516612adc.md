## Capability
Expose versioned selectable world-map snapshots with persistent selection, locale-aware names, manifest-bounded topology navigation, recoverable loading, place details, and mapped-BGM playback.

## Semantics
Selection always resolves to one exact selectable snapshot identity. Resolution priority is: valid explicit route snapshot; remembered selectable snapshot; latest selectable GMS snapshot; catalog default snapshot. An explicit invalid/unselectable route value resolves to catalog default. Remembered selection is persistent and portable. A snapshot switch commits only after the candidate manifest is ready; before that it is only a candidate. Display labels prefer exact browser-locale matches, then same-language localized names, then canonical/world-map-name fallback. Missing topology remains explicit rather than guessed. Mapped BGM delegates to the existing Playback contract without World Map-specific exceptions.

## Rules
- Only catalog entries marked selectable may become selected.
- Valid explicit route snapshot has highest priority.
- Invalid/unselectable explicit route snapshot falls back to catalog default.
- Without explicit route input, prefer remembered selectable snapshot, then latest selectable GMS, then catalog default.
- Persist the last successfully selected snapshot and include it in portable Saved Data.
- Do not durably commit a candidate snapshot until its manifest has loaded successfully.
- If a candidate switch fails while a usable snapshot exists, retain the previous usable selected/remembered snapshot.
- If initial candidate loading fails with no usable snapshot, preserve candidate intent and expose retry rather than silently choosing another snapshot because of the load failure.
- A remembered catalog-selectable snapshot must not be cleared solely due to manifest load failure.
- Browser locale resolution is exact locale -> same language -> canonical/world-map-name fallback.
- Navigation must remain bounded by the committed snapshot's declared topology.
- Missing link/parent/spot targets must not be replaced by fabricated targets.
- Mapped BGM playback reuses normal music/playability and playback-transition rules.

## Edge Cases
A remembered snapshot that is no longer selectable is skipped by resolution fallback rather than forced. A remembered selectable snapshot whose manifest temporarily fails stays remembered. Missing localized names fall through deterministically to canonical display. A broken topology reference remains unresolved even if a plausible nearby target exists. Failed node loading must not fabricate node content and may be retried. A failed candidate switch must not erase the previous usable snapshot state.

## Reverse-spec evidence
Observed in world-map view/composable/schema and resources output. Product review explicitly accepted snapshot resolution priority, portable remembered selection, locale fallback order, explicit unresolved topology, manifest-ready commit semantics, and Playback reuse. Current implementation commits selected/remembered identity before manifest readiness, so that state transition is an implementation gap rather than normative truth. Progressive loading/cache/chunk mechanics remain non-normative.
