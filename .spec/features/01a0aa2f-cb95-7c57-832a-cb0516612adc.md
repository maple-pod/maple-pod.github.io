## Legacy Feature notes

## Capability
Explore a selected historical world-map snapshot and connect its places to MapleStory music.

## Semantics
World Map presents one exact selected snapshot at a time. Selection is deterministic, remembered selection is portable, and a candidate becomes committed only when its manifest is ready. Navigation is bounded by the committed snapshot's topology. Labels use a deterministic browser-locale fallback, and mapped BGM uses ordinary Playback semantics.

## Rules
- Only selectable catalog snapshots can become the committed selection.
- A failed candidate switch must not destroy a previously usable committed context.
- An initial failed candidate remains recoverable through its error/retry path rather than being silently replaced solely because loading failed.
- Missing topology targets remain unresolved rather than being fabricated.
- World Map does not create special playability or playback-transition exceptions for mapped music.

## Edge Cases
A remembered but no-longer-selectable snapshot is skipped. A remembered selectable snapshot survives transient manifest failure. Missing localized names and broken links use the contract's fallback or unresolved state without mixing snapshots.

## Legacy Requirement notes: World-map snapshot selection and navigation behavior

## Contract
Maple Pod must expose only world-map snapshots declared selectable by the resource catalog and must resolve one exact selected snapshot identity.

Snapshot resolution must follow this order: a valid explicit route snapshot; otherwise a remembered selectable snapshot; otherwise the latest selectable GMS snapshot; otherwise the catalog default snapshot. An explicit route snapshot that is invalid or unselectable must resolve to the catalog default snapshot. The last successfully selected snapshot identity must persist across reloads and must participate in portable Saved Data transfer. If a remembered identity is no longer selectable, resolution must continue to the next fallback rather than forcing that stale selection.

A requested snapshot switch must be treated as a candidate transition until that snapshot's manifest loads successfully. Only manifest readiness may commit the new selected snapshot and remembered preference. If a candidate switch fails while another usable snapshot is already active, Maple Pod must retain the previous usable selected snapshot and remembered preference. A failed candidate must not replace durable selection merely because it was requested.

On initial World Map entry when no previous usable snapshot exists, a resolved candidate whose manifest fails to load must remain the intended target, expose a user-observable error and retry path, and must not silently select another fallback solely because of the load failure. If a remembered snapshot is still catalog-selectable, transient manifest load failure must not delete or rewrite that remembered preference.

Navigation must stay within the committed snapshot's declared topology. Links, breadcrumb parents, roots, and spots must not silently fabricate missing targets. Unresolved targets must remain explicitly unavailable/unresolved. Node-loading failures must remain recoverable and must not invent node content.

World-map display names must follow browser locale preference order: first exact locale match, then an available same-language localized name, then canonical/world-map-name fallback.

A mapped music action must delegate to the existing Playback contract. World Map must not introduce a separate exception for resolvability, playability, disabled state, or playback transition success.

## Rationale
Snapshot identity is historical context, so navigation and labels must remain bound to one explicit dataset rather than mixing data across versions. Committing only after manifest readiness prevents a failed candidate from destroying a working context or corrupting remembered preference. Preserving a still-selectable remembered identity through transient load failure distinguishes preference validity from resource availability.

## Verification
Exercise valid/invalid/unselectable explicit snapshot routes, remembered selection, missing remembered selection, latest-selectable-GMS fallback, and catalog-default fallback. Export/import Saved Data and verify snapshot selection transfer. Switch from a working snapshot to a candidate whose manifest fails and confirm the previous selection remains committed and remembered. On initial load, fail the resolved manifest and confirm error + retry without silent fallback or preference deletion. Exercise exact locale, same-language fallback, and canonical fallback. Navigate roots/links/breadcrumbs/spots with valid and unresolved targets, retry a failed node, and exercise mapped playable/unplayable BGM through the normal Playback contract.
