## Legacy Feature notes

## Capability
Publish a self-consistent music, background, and optional loudness resource bundle for Maple Pod consumption.

## Semantics
Each current music entry declares its identity, metadata, duration, and actual audio representation. Referenced media and visual assets resolve consistently with the catalog. Optional loudness data is tied to the same resource build and remains governed by the Playback normalization contract. Consumers use declared representations rather than guessing legacy paths.

## Rules
- Current-format resources must satisfy the explicit representation and asset-consistency contract.
- Missing or mismatched required resources invalidate the bundle.
- Loudness data may be absent for ordinary playback resources, but present data is usable only when its separate contract is satisfied.

## Edge Cases
An undeclared or missing audio representation fails closed rather than invoking a filename heuristic. A missing optional loudness report does not invalidate otherwise usable music and visual resources.

## Legacy Requirement notes: Frontend-consumable static resource bundle

## Contract
A published current-format music resource bundle must provide, for every track, stable music identity, metadata/title, duration, and an explicit actual audio representation identifying the published file, codec, and container. Every audio file referenced by the catalog must exist and agree with that representation. Referenced mark imagery and background catalog assets/previews must likewise exist and resolve consistently.

Maple Pod must consume the declared audio representation directly. It must not treat an undeclared `${musicId}.mp3` path as a compatibility fallback for current-format resource entries.

A loudness report, when published, must identify the resource build it analyzes and is usable only according to the separately accepted loudness-normalization eligibility contract. The music/background bundle remains publishable without loudness normalization data so long as its own required resource references are valid.

## Rationale
Explicit representations prevent the frontend from guessing stale file extensions or formats and keep the static resource contract self-describing. Asset self-consistency allows publication and frontend validation to fail closed instead of hiding broken builds behind legacy path heuristics.

## Verification
Build a current resource bundle and verify every track has stable identity, metadata/title, duration, and explicit `audio.file`/codec/container. Resolve every catalog-referenced audio, mark, and background asset. Remove or corrupt each class of reference and confirm validation/consumption fails closed rather than guessing `${musicId}.mp3`. Verify loudness build identity/coverage independently through the Playback loudness contract.
