## Capability
Provide queue-based audio playback for a playlist, including current-item state, playback navigation and controls, seek, volume, and mute behavior.

## Semantics
Starting playback establishes a source playlist and queue. Queue selection and navigation operate only on items currently considered playable. Random mode is a supported playback mode that changes queue ordering. Repeat behavior has three supported states: `off`, `repeat`, and `repeat-1`. A candidate item becomes the current track only after its source resolves and playback starts successfully.

## Rules
- A requested starting music item must belong to the selected playlist.
- Queue initialization and navigation must skip items that are currently unavailable for playback.
- The playback feature consumes playability as an input and does not define the connectivity/offline rules that determine it.
- Next/previous navigation skips unavailable items.
- Previous restarts the current music after more than three seconds of playback; at three seconds or less it navigates backward in the queue.
- The user can seek within the current track.
- `repeat-1` loops the current source; `repeat` continues by selecting another playable queue item and restarts the same item when it is the only playable choice.
- Random, repeat, volume, and muted state are persisted as playback preferences across reloads.
- Current track, queue position, and elapsed playback time are not required by this feature to persist across reloads.
- A source-resolution or playback failure must not complete the current-track transition to the failed item.

## Edge Cases
Empty playlists, fully unavailable queues, stale/unknown music IDs, asynchronous source changes, seek boundaries, and source playback errors must not produce an invalid current-source transition.

## Reverse-spec evidence
Observed in `src/composables/useAudioQueue.ts`, `src/composables/useAudioPlayer.ts`, `src/composables/useMusicStore.ts`, and `src/composables/useSavedUserData.ts`. Random playback, repeat modes, Previous threshold, seek, skip-unplayable behavior, current-track transition semantics, and persisted preference scope were explicitly accepted during reverse-spec review; lower-level timing/fade and playability-detection mechanisms remain non-normative.
