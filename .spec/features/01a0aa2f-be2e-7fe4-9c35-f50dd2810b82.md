## Legacy Feature notes

## Capability
Apply persistent appearance preferences for theme and application background.

## Semantics
Theme and background are independent preferences. Theme may follow system appearance dynamically. Background presentation may be absent, automatic, or tied to a selected catalog identity; automatic presentation changes over time among eligible backgrounds. A temporarily unavailable selected identity is a display problem, not a request to rewrite the preference.

## Rules
- Appearance preferences persist independently and are portable saved data.
- System-following theme responds to later system preference changes.
- Automatic background presentation uses the accepted rotation policy.
- A missing selected background renders safely while preserving the stored identity.

## Edge Cases
An unavailable or empty background catalog must not break application rendering. When a missing selected identity becomes available again, the preserved preference may take effect without reconfiguration.

## Legacy Requirement notes: Appearance preference behavior

## Contract
Maple Pod must persist theme and background preferences independently and include them in portable saved data.

Theme must support exactly three product modes: Light, Dark, and Auto/System. Light and Dark force their respective application appearance. Auto/System must follow the operating system's current color scheme and must update when the system preference changes.

Background must support three product modes: None, Auto, and Specific catalog background identity. None renders no application background. Specific renders the selected catalog background when that identity is available. Auto must rotate among available catalog backgrounds on a five-minute interval. The ordering/randomization algorithm is not normative.

If a saved Specific background identity is absent from the current catalog, Maple Pod must render safely as if no background were available while preserving the stored identity unchanged. The preference must not be normalized to None merely because the catalog temporarily lacks that identity. If the identity later returns, the saved selection may take effect again.

If background resources cannot load or no eligible backgrounds exist, application rendering must remain functional and background presentation must degrade safely.

## Rationale
Appearance is user preference rather than content state. Preserving stale Specific identities avoids destructive preference rewriting during transient catalog changes, while a fixed five-minute Auto interval makes the user's expected rotation behavior stable and testable.

## Verification
Select each theme mode and reload. While Auto/System is selected, change OS color scheme and confirm the application follows it. Select None and a valid Specific background and reload. Select Auto and confirm background advances on the five-minute interval when multiple eligible backgrounds exist. Persist a Specific identity, remove it from the available catalog, confirm rendering falls back safely without rewriting the saved identity, then restore the identity and confirm it can become effective again.
