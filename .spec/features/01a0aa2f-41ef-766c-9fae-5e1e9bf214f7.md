## Capability
Prepare and manage an exact world-map snapshot revision for offline exploration with trustworthy completeness and integrity semantics.

## Semantics
`ready` means the selected snapshot revision's required runtime resources are complete and verified against the current revision/manifest identity. Presence of partial cache data is not sufficient. A failed/incomplete state can be retried directly, and implementation may reuse partial data while rebuilding verified readiness.

## Rules
- Download, progress, cancel, remove, visible failure, and direct retry are product-level lifecycle behaviors.
- Partial or failed snapshot data must not be reported as ready.
- Ready state must be revision-matched and integrity-verified for the current snapshot runtime contract.
- A manifest/revision change invalidates readiness established for the prior revision.
- Partial-data reuse is permitted as an implementation optimization but does not create partial readiness.

## Edge Cases
Cached resources from an older manifest, incompatible schema, cancelled preparation, or incomplete/failed acquisition must remain not-ready. A retry may reuse valid retained resources, but only the complete current snapshot revision may transition to ready. Removal clears the product-level readiness state for that snapshot even if implementation-specific cache cleanup is best-effort.

Observed in `src/composables/useWorldMapOffline.ts`, `src/composables/useWorldMaps.ts`, and `src/views/WorldMap.vue`. These readiness and recovery semantics were explicitly accepted during Offline reverse-spec review.
