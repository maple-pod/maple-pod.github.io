## Legacy Feature notes

## Capability
Provide generic application-shell offline reuse and a user-controlled update lifecycle for the web app.

## Semantics
The application may expose generic offline shell readiness and update readiness as separate user-visible states. A ready update does not change the current page until the user chooses to reload. Generic shell readiness is independent from verified Music and World Map offline readiness.

## Rules
- Supported browsers may receive generic offline shell behavior and a readiness indication.
- A newer application version is surfaced as an update choice rather than an automatic disruptive switch.
- Dismissing the update choice leaves the current session running.
- Generic shell state cannot satisfy content-specific offline contracts.

## Edge Cases
Browsers without the supported capability continue as ordinary web applications. Generic cached content may be useful without proving that any specific music or map content is ready offline.

## Legacy Requirement notes: PWA availability and update-notification behavior

## Contract
Where the browser supports Maple Pod's PWA offline/update capability, Maple Pod must provide a reusable application shell sufficient for its supported generic offline behavior and must expose a user-visible indication when that app-shell offline capability becomes ready.

When a newer deployed Maple Pod application version becomes available through the supported update lifecycle, Maple Pod must expose a user-visible update-ready state. The application must not silently force a disruptive page reload/version switch merely because new content is ready. The current page/session must continue until the user explicitly chooses Reload. Closing or dismissing the update notification must not itself apply the update through a forced reload.

After explicit Reload, Maple Pod may activate/apply the available worker/update and reload into the newer application version.

Generic PWA app-shell readiness is distinct from explicit content-offline readiness. Generic application-shell state must not be used as proof that a music track, playlist, or World Map snapshot satisfies its corresponding explicit offline download/integrity/readiness contract. Those capabilities remain governed by their own normative contracts.

If the PWA offline/update capability is unsupported or unavailable, Maple Pod may operate as a normal online web application; lack of that capability must not by itself make the primary application unusable.

## Rationale
A PWA shell improves resilience and return usage, while explicit Reload keeps disruptive version switches under user control. Keeping generic cache state separate from verified content-offline readiness avoids weakening the stricter guarantees already defined for downloaded music and World Map snapshots.

## Verification
On a browser with the supported PWA offline/update capability, allow the app shell to become offline-ready and verify a user-visible readiness notice. Revisit with network unavailable and verify the supported shell remains usable. Make a newer application build available, verify update readiness is surfaced without automatic page reload, dismiss the notice and confirm the current page remains running, then explicitly choose Reload and verify the new version loads. Separately establish generic application-shell offline state without completing explicit Music/World Map downloads and verify those capabilities are not reported offline-ready solely from generic shell state. Test a browser/environment without the PWA capability and verify ordinary web-app use remains possible.
