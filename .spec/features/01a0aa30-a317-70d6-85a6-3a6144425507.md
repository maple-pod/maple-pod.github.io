## Capability
Publish exact region/version world-map snapshots through an explicit versioned compatibility contract, with verified canonical graph/runtime resources, snapshot-bound provenance, integrity metadata, explicit unresolved references, and strict catalog selectability gates.

## Semantics
Canonical, runtime, and catalog artifacts carry explicit schema/contract versions. Consumers accept supported versions and fail closed on unsupported versions; the contract requires versioning but does not permanently freeze today's implementation numbers. Each snapshot declares the canonical source/provenance authority for that exact region/version, and all canonical graph/runtime data must agree with it. A production snapshot becomes selectable only after full verification of canonical graph, runtime representation, referenced assets, provenance/source identity, and declared fingerprints. Preview output is isolated and non-selectable. Previously selectable output is not sticky: revalidation failure demotes it. Missing graph references remain explicit. The legacy unversioned compatibility alias is not part of new publication semantics and must stop being generated.

## Rules
- Snapshot identity is exact logical region + version.
- Canonical/runtime/catalog artifacts must declare explicit compatibility versions.
- Unsupported artifact versions must fail closed.
- Current concrete version numbers are implementation/current compatibility state, not permanent normative constants.
- Each snapshot must declare its canonical source/provenance authority.
- Canonical graph/runtime provenance must match the declared source for that snapshot.
- Enrichment/localization may supplement display data but must not rewrite canonical identity/provenance.
- Only verified full snapshots may be catalog-selectable.
- Preview/partial snapshots must remain isolated and non-selectable.
- Canonical graph, runtime manifest/chunks, referenced assets, provenance/source identity, and declared fingerprints must agree before selectability.
- A previously selectable snapshot must be demoted if later revalidation fails.
- Missing parent/link targets must remain explicit rather than silently repaired.
- Legacy unversioned canonical/runtime alias output must not be generated as part of the desired publication flow.
- Provider acquisition/caching algorithms remain implementation details except where the declared source authority determines canonical provenance.

## Edge Cases
A snapshot built under an unsupported schema version is not consumed by guessing field layout. A stale previously-selectable artifact that no longer passes verification must become non-selectable. A preview that happens to contain valid-looking data still cannot become production-selectable. A localization provider may fail without changing canonical identity. Removing the unversioned legacy alias must not change the versioned snapshot identity contract.

## Reverse-spec evidence
Observed in resources world-map source/tests and frontend schema consumers. Product review explicitly accepted versioned compatibility without permanently freezing current v8/v3/v1 values, strict full selectability, revalidation demotion, snapshot-bound canonical provenance, explicit unresolved references, and removal of legacy unversioned alias generation.
