## Capability
Expose playlist-derived mark facets to narrow visible music and allow a known music item to be located and revealed in a target playlist.

## Semantics
Mark filtering is an ephemeral presentation operation over resolvable playlist tracks, not a membership mutation or saved preference. Available marks come from the current playlist's resolvable tracks; empty marks are excluded. Multiple selected marks use OR semantics and no selected marks means the full resolvable playlist is shown. Track-location navigation reveals an existing member in playlist context without changing membership.

## Rules
- Derive filter marks only from resolvable tracks in the viewed playlist.
- Omit empty marks from the selectable filter set.
- Match a track when its mark is any selected mark.
- Treat zero selected marks as no filtering.
- Distinguish a no-results filter outcome from an actually empty playlist.
- Clear active mark filtering when the user leaves the current playlist context or reloads the application.
- A locate action must not add, remove, or reorder playlist membership.
- Successful locate must reveal the target even when the pre-existing filter state would otherwise hide it; how presentation is adjusted is implementation detail.

## Edge Cases
If a known music item is not a member of the requested target playlist, locate produces no membership side effect. If playlist resources no longer resolve, unavailable tracks do not create selectable mark facets. A conflicting active filter cannot make a successful locate outcome invisible.

## Reverse-spec evidence
Observed in `src/views/Playlist.vue`, `src/components/PlaylistFilterDropdown.vue`, `src/components/MusicDropdownMenu.vue`, and `src/composables/useAppStore.ts`. OR filtering, ephemeral lifetime, and track-location reveal behavior were explicitly accepted during product review.
