## Legacy Feature notes

## Capability
Narrow a playlist presentation by music marks and reveal a known member in playlist context.

## Semantics
Filtering is derived presentation over the current resolvable playlist. It is temporary, does not mutate collection state, and combines selected marks according to the accepted matching semantics. Locate is navigation to an existing member, not membership mutation.

## Rules
- Only marks supported by resolvable playlist tracks are offered.
- No selected mark means the unfiltered resolvable playlist; selected marks use the accepted match relation.
- Filter state ends with the playlist context or an application reload.
- A successful locate must make the target visible even if current presentation would hide it.

## Edge Cases
No matches remain distinct from an empty playlist. A missing or non-member locate target has no membership side effect. Unavailable tracks do not create filter choices.

## Legacy Requirement notes: Playlist filtering and track-location behavior

## Contract
Maple Pod must let a user narrow the visible tracks of a resolved playlist by available music marks without mutating playlist membership or order. Available marks must be derived from resolvable tracks in that playlist and empty marks must not be offered. With no selected marks, all resolvable tracks must be shown. With multiple selected marks, a track must be shown when its mark matches any selected mark.

Selected marks are ephemeral state for the current playlist view. They must not be persisted as saved user data and must be cleared when the user leaves that playlist context or reloads the application.

A no-match filter outcome must be distinguishable from an actually empty playlist. Maple Pod must also support locating a known music item in a target playlist when membership can be resolved. A successful locate action may navigate and adjust presentation as needed, but it must visibly reveal the target and must not mutate playlist membership or ordering.

## Rationale
Filtering and location are discovery/navigation behaviors. Keeping them separate from playlist mutation and saved preferences prevents a presentation action from changing durable collections while still making locate meaningful under an active filter.

## Verification
Exercise no filter, one mark, multiple marks, no-match, playlist change, and reload. Verify OR semantics, no-selection = all, and ephemeral lifetime. Use Show in All / equivalent locate behavior both with no filter and with a conflicting filter; successful locate must reveal the requested track while membership/order remain unchanged. Verify an unresolvable locate target creates no playlist mutation.
