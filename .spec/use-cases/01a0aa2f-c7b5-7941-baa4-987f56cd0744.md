## Preconditions
A world-map snapshot catalog and at least one selectable snapshot can be loaded.

## Main Flow
1. Maple Pod resolves one exact selectable snapshot identity.
2. An explicit valid route snapshot has highest priority.
3. Without a valid explicit route snapshot, Maple Pod prefers a remembered selectable snapshot; otherwise it falls back to the latest selectable GMS snapshot, then the catalog default snapshot.
4. An explicit invalid or unselectable snapshot resolves to the catalog default snapshot.
5. The remembered snapshot selection persists and participates in portable Saved Data transfer.
6. When switching snapshots, the requested snapshot is only a candidate until its manifest loads successfully.
7. After the candidate manifest is ready, Maple Pod commits the new selected snapshot and remembered selection.
8. The user navigates roots, breadcrumbs, links, and map spots within the committed snapshot topology.
9. Display names follow browser locale preferences using exact-locale match, then same-language localization, then canonical/world-map-name fallback.
10. A place with a mapped BGM delegates playback entirely to the normal Playback capability.

## Alternate & Failure Flows
- If switching from an already usable snapshot and the candidate manifest fails to load, the previous usable snapshot remains selected and remembered; the failed candidate is not durably committed.
- On initial entry with no previous usable snapshot, a failed resolved candidate remains the user's intended target, exposes an error with retry, and is not silently replaced by another snapshot solely because loading failed.
- A remembered snapshot that is still catalog-selectable is not cleared merely because its manifest load fails; transient load failure does not rewrite preference.
- Link, breadcrumb-parent, or spot targets that cannot be resolved remain explicitly unavailable/unresolved; Maple Pod must not invent a replacement target.
- Node load failures remain recoverable through retry.

## Observable Outcomes
World Map resolves a deterministic selectable snapshot, commits snapshot changes only after manifest readiness, preserves the user's remembered selection across reload/transfer when still selectable, localizes labels according to browser preference, and never silently fabricates missing topology. Failed switching does not destroy a previously usable map context.

## Reverse-spec evidence
Observed in `src/views/WorldMap.vue` and `src/composables/useWorldMaps.ts`. Snapshot priority, remembered-selection portability, locale fallback order, explicit unresolved topology, manifest-ready commit semantics, retry behavior, and reuse of the existing Playback contract were explicitly accepted during product review. The manifest-ready commit rule is stricter than current implementation and should be treated as normative intent.
