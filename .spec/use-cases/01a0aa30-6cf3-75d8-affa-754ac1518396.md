## Preconditions
A playback session can be controlled and the platform may support one or more auxiliary control surfaces.

## Main Flow
1. The user may toggle playback with the Space key when focus is not in an interactive/editable control.
2. Modified Space events and repeated keydown events do not toggle playback.
3. Supported browser Media Session controls expose current-track metadata and delegate play/pause, previous, next, and seek to the same active playback session.
4. Supported Document Picture-in-Picture can host the same player UI in a separate compact window and returns that same player context when the auxiliary window closes.
5. While playback is actively playing, Maple Pod requests the browser's unload confirmation safeguard before page close/navigation; paused playback does not require that safeguard.

## Alternate & Failure Flows
- Unsupported Media Session or Document Picture-in-Picture capabilities simply leave those surfaces unavailable; primary playback remains functional.
- Keyboard handling must not hijack ordinary interactive/editable controls.
- Auxiliary surfaces must never create an independent queue, current-track state, or playback session.

## Observable Outcomes
Playback state, queue position, seek position, metadata, and transport actions remain consistent across the primary player, keyboard shortcut, Media Session controls, and Document Picture-in-Picture. Active playback receives an exit safeguard while paused playback can unload normally.

## Reverse-spec evidence
Observed in `src/components/MusicPlayer.vue`, `src/composables/useMusicStore.ts`, `src/composables/useDocumentPictureInPicture.ts`, and `src/App.vue`. Product review explicitly accepted Space, Media Session, and Document Picture-in-Picture as formal auxiliary surfaces, fixed the current Space suppression behavior, accepted the active-only unload safeguard, and required a single shared playback session.
