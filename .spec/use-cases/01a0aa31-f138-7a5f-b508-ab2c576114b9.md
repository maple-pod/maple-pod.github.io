## Preconditions
The application can render dialogs and can persist device/browser-local onboarding state.

## Main Flow
1. On the first recorded visit for that browser/device, Maple Pod proactively opens the About/context notice once.
2. The notice communicates all required semantic content: Maple Pod's fan-made MapleStory BGM player identity; music metadata/source context; personal-listening/non-commercial-use intent; a copyright-owner contact path; non-affiliation with game development/operation organizations; and the running build identity.
3. The user dismisses the notice.
4. Maple Pod persists that dismissal locally on the browser/device so later normal visits do not automatically reopen it.
5. The user can manually reopen About from Settings at any later time.

## Alternate & Failure Flows
- The dismissal state is not part of portable Saved Data and does not transfer to another browser/device.
- Normal Reset Saved Data does not clear this first-visit/onboarding dismissal state.
- Factory Reset or external clearing of the relevant browser storage removes the dismissal state, so the next visit is treated as first recorded visit again.
- Exact wording may change as long as the required semantic content remains clear and non-misleading.

## Observable Outcomes
A new browser/device sees the disclosure proactively once; after dismissal it stays quiet across normal reloads/visits until Factory Reset or storage clearing, while About remains manually accessible. The displayed build identity corresponds to the running build.

## Reverse-spec evidence
Observed in `src/App.vue`, `src/components/AboutDialog.vue`, and `src/components/SettingsDropdownMenu.vue`. Product review explicitly accepted the first-visit lifecycle, persistence boundary, required disclosure content, and semantic wording policy.
