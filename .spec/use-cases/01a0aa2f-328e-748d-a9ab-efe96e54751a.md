## Preconditions
Music metadata is available and the application can determine the current audio source representation for each track.

## Main Flow
1. The user requests offline availability for an individual music item or all current members of a saveable Liked/custom playlist.
2. Maple Pod exposes download progress while the request is active.
3. The user may cancel an active download.
4. Successfully saved media becomes ready for offline playback only when it corresponds to the current catalog source representation for that music identity.
5. The user may remove saved offline media.
6. A failed or incomplete download may be requested again directly without requiring a prior remove operation.

## Alternate & Failure Flows
- Download failure must be observable to the user and must not be reported as ready.
- Partial/incomplete saved data is not ready. Implementation may retain reusable partial data for a later retry, but retained partial data must not make the music appear offline-ready.
- If a previously saved media representation no longer matches the current catalog source representation, it is stale and must not remain ready.
- Offline playback must treat music without a current ready offline representation as unplayable while connectivity is unavailable.

## Observable Outcomes
The user can distinguish pending, progressing, failed/incomplete, ready, and removed outcomes sufficiently to manage offline music. Saveable playlist bulk download operates over the playlist's current music membership; the playlist itself is not a separate offline payload.

## Reverse-spec evidence
Observed in `src/composables/useMusicStore.ts`, `src/components/MusicDropdownMenu.vue`, `src/components/PlaylistDropdownMenu.vue`, and `src/components/DownloadManagerDropdownMenu.vue`. Product review explicitly accepted source-bound readiness, visible failure, not-ready partial state, direct retry, full lifecycle management, and Liked/custom playlist bulk download.
