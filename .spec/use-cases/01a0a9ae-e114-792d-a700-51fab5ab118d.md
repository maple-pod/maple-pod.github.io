## Preconditions
The application data is ready, the selected playlist resolves, and at least one selected or queued music item is playable.

## Main Flow
1. The user starts playback from a playlist or music item.
2. Maple Pod initializes a queue and chooses the requested item or the first playable item.
3. The player resolves the selected source and begins playback.
4. Only after playback starts successfully does the selected item become the current track.
5. The user may pause/resume, seek within the current track, move to previous/next music, toggle random order, cycle repeat behavior, adjust volume, or mute/unmute.
6. Playback state and the remaining queue update as the session progresses.

## Alternate & Failure Flows
- An empty playlist, an unknown requested item, or a playlist with no playable item does not start a queue.
- Items that are currently unavailable for playback are skipped while initializing or navigating the queue; the playback chain does not define how availability is determined.
- Previous restarts the current music when playback has progressed beyond three seconds; otherwise it navigates backward in the queue.
- Source resolution or playback failure does not complete a transition to that item as the current track.

## Observable Outcomes
The UI exposes current music, play/pause state, seek position, queue ordering, random state, repeat state, volume, muted state, elapsed time, and navigation controls.
