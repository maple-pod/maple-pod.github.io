## Preconditions
A selectable world-map snapshot and its runtime manifest are available.

## Main Flow
1. The user requests offline preparation for the selected world-map snapshot revision.
2. Maple Pod exposes download progress while required runtime resources are being acquired.
3. The user may cancel the active download.
4. The snapshot becomes ready only after all runtime resources required for that exact revision have been obtained and verified consistently.
5. The user may remove the saved snapshot.
6. A failed or incomplete snapshot download may be requested again directly.

## Alternate & Failure Flows
- Download failure must be observable and must not be reported as ready.
- Partial saved snapshot data is not ready. It may be retained for reuse by a later retry, but such reuse is implementation detail.
- If the snapshot manifest/revision identity changes, data from the previous revision must not satisfy readiness for the new revision.

## Observable Outcomes
The user can distinguish downloading, failed/incomplete, ready, and removed states for a world-map snapshot and can retry failed/incomplete preparation without a required manual removal step.

## Reverse-spec evidence
Observed in `src/composables/useWorldMapOffline.ts` and `src/views/WorldMap.vue`. Product review explicitly accepted strict verified readiness, visible failure, not-ready partial state, direct retry, and the common download/progress/cancel/remove lifecycle.
