## Preconditions
An exact logical region/version can be acquired from a supported source and the BGM catalog is available for track-selection evidence.

## Main Flow
1. Maintainers generate an isolated preview or a production full snapshot for one exact logical region/version identity.
2. Full generation builds canonical graph data plus versioned runtime manifest/node chunks/assets.
3. Every published canonical/runtime/catalog artifact declares an explicit schema/contract version supported by its consumer.
4. The snapshot declares the canonical source/provenance authority used for that exact region/version, and canonical graph/runtime data must agree with it.
5. Validation checks schema compatibility, topology/integrity, declared provenance, runtime self-consistency, referenced assets, and content fingerprints.
6. Only a successfully verified full artifact becomes catalog-selectable.
7. A previously selectable snapshot that later fails revalidation is demoted to non-selectable.
8. Preview output remains isolated and cannot make a production snapshot selectable.
9. Unsupported schema/contract versions fail closed rather than being guessed or silently coerced.
10. Known missing parents/link targets remain explicit unresolved references and are not silently rewritten into different topology.
11. The legacy unversioned world-map compatibility alias is not part of the desired publication path and must no longer be generated.

## Alternate & Failure Flows
- Preview/partial output remains non-selectable even if internally readable.
- Missing or inconsistent canonical/runtime/assets/provenance/fingerprint/schema compatibility blocks selectability.
- Enrichment/localization from other regions/providers must not rewrite the snapshot's canonical identity or provenance authority.
- Revalidation failure removes selectability rather than preserving a stale successful state.

## Observable Outcomes
Every selectable snapshot is an exact versioned, fully verified publication whose canonical graph/runtime match the declared snapshot provenance. Consumers never need the unversioned legacy alias to access newly published snapshots, and unresolved topology remains explicit.

## Reverse-spec evidence
Observed in sibling repo world-map generation/runtime/schema/validation code and frontend consumers. Current shipped implementation uses canonical v8/runtime v3/catalog v1, while README still contains stale v7 wording; product review accepted versioned compatibility semantics without freezing those current numbers as permanent. Strict full verification, revalidation demotion, snapshot-bound provenance authority, explicit unresolved references, and removal of legacy alias generation were explicitly accepted.
