## Preconditions
The resource-maintenance environment can acquire the configured MapleStory music metadata/media and tracked background assets.

## Main Flow
1. The pipeline produces a self-consistent music catalog with stable music identity, metadata/title, duration, the actual published audio representation (`file`, `codec`, and `container`), mark imagery, and a build identity.
2. Every catalog-referenced audio/mark asset exists and agrees with the published representation.
3. The pipeline produces a background catalog whose listed backgrounds/previews resolve to published assets.
4. Loudness analysis may produce a report tied to the same resource build and is consumed only under the separate Playback loudness eligibility contract.
5. Frontend consumers resolve the declared current audio representation directly; legacy `${musicId}.mp3` guessing is not part of the accepted publication contract.

## Alternate & Failure Flows
- Missing or inconsistent referenced assets make the bundle invalid for publication/consumption.
- A track without the declared actual audio representation is not a valid current-format bundle entry.
- Source acquisition tools, batch sizes, download retries, transcoding/remux choices, and deployment batching remain implementation mechanisms.

## Observable Outcomes
A published bundle can be consumed without guessing an undeclared audio filename or format, and every referenced music/mark/background asset resolves consistently.

## Reverse-spec evidence
Observed in sibling repo `build-resources.ts`, `processBgs.ts`, `analyze-loudness.ts`, README, and frontend `useMusicStore.ts`. Product review explicitly accepted strict bundle self-consistency and rejected the current legacy MP3 fallback as desired behavior.
