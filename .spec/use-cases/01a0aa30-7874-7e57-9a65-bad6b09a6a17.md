## Preconditions
The current music catalog has loaded. A loudness-analysis report and an audio output path capable of applying gain may or may not be available.

## Main Flow
1. Maple Pod loads loudness measurements associated with the current music-resource build.
2. Normalization becomes eligible only when the report has zero analysis failures, its success/track counts exactly match the current catalog, and its `resourceBuiltAt` exactly matches the current resource build.
3. For an eligible report, each track uses the accepted normalization policy: target integrated loudness -16 LUFS with a -1 dBTP true-peak ceiling.
4. The applied gain is the smaller of the gain needed to reach -16 LUFS and the gain allowed before exceeding -1 dBTP.
5. When the active output path supports normalization, Maple Pod automatically applies the per-track gain during playback.
6. If the report is missing, incomplete, stale/mismatched, failed, or the output path cannot safely apply normalization, playback continues through the ordinary non-normalized path.

## Alternate & Failure Flows
- A report with any failed analysis is ineligible as a whole; Maple Pod must not partially normalize only the successful tracks.
- A report whose track counts differ from the current catalog is ineligible as a whole.
- A report from a different `resourceBuiltAt` is ineligible as a whole.
- Failure to create, resume, or use the enhanced audio-output path must bypass normalization rather than block ordinary playback.

## Observable Outcomes
On capable platforms with a complete matching report, track-to-track loudness differences are automatically reduced using the fixed -16 LUFS / -1 dBTP policy. On unsupported or failed normalization paths, tracks remain playable without normalization.

## Reverse-spec evidence
Observed in `src/composables/useMusicStore.ts`, `src/utils/loudness.ts`, `src/composables/useAudioOutput.ts`, and `src/composables/useAudioPlaybackBackend.ts`. Product review explicitly accepted automatic normalization as a Playback capability, strict all-or-nothing report eligibility, the -16 LUFS / -1 dBTP gain policy, and safe bypass when normalization is unavailable.
