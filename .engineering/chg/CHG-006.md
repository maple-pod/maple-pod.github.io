## Rationale

The maintainer authorized publishing loudness normalization as a normal persisted Experimental setting after full-catalogue analysis and browser verification showed that a -16 LUFS target with a -1 dBTP ceiling provides useful level matching without modifying source audio.

## Sources

- Maintainer decision in maple-pod/resources Issue #3 to ship the work as an experimental feature toggle rather than a URL-gated A/B prototype.
- Phase 1 full-catalogue analysis in maple-pod/resources Issue #3: 1,360/1,360 tracks measured, with -16 LUFS / -1 dBTP selected for the first experiment.
- Phase 2 Chromium verification against representative WebM/Opus, M4A/AAC, quiet, loud, and peak-limited tracks.

## Changes

- Introduced REQ-013 defining the persisted, default-off Experimental Loudness Normalization behavior and fallback contract.
- Introduced ADR-008 defining the separate Web Audio normalization, transition, and user-volume gain stages.
- Added a lazy loudness-metadata path tied to the current resource build and a persisted Settings > Experimental toggle.
- Kept source audio, queue identity, offline source selection, and existing default-off playback behavior unchanged.

## Verification

Result: passed

- `pnpm lint` passed.
- `pnpm type-check` passed.
- `pnpm build` and theme verification passed.
- `ef validate --scope snapshot` passed before integration.
- Chromium playback verified exact expected gain for DragonDream, AsylumAmbience, next, and SecretMissionBase, including positive gain above unity and an M4A peak-limited case.
- Playback-time toggle verification showed the active media source and seek progression remained unchanged while normalization gain moved between bypass and the calculated value.
- Saved-data compatibility verification confirmed pre-existing data without the experimental preference resolves it to `false`.
