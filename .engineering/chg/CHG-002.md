## Rationale

The playlist mark filter (PRD-001) shipped without any feedback about what it hides. A filter that matches nothing produced a completely blank track list, indistinguishable from a broken or empty playlist, and nothing told the user how much of the list the active filter removed. Browser inspection of the pre-change build confirmed that the filter dropdown's "No marks available" empty state already existed, but the zero-result message and the result count did not. This transaction implements the missing feedback and promotes REQ-002 from draft to active as the requirement of record.

## Sources

- PRD-001 "Playlist Mark Filter" - the product intent this feedback gap belongs to.
- Original feature plan items EMPTY-01..03, carried into REQ-002 as remaining scope.
- Direct maintainer decision (2026-08-11): the maintainer asked to verify whether REQ-002 was genuinely unimplemented, accepted the corrected scope, and then asked to implement it.
- Observed pre-change behavior verified in a browser against the dev build: an active filter matching zero tracks rendered a blank list area with no message, and no track count was displayed anywhere while filters were active.

## Changes

- REQ-002 "Filter Empty States and Result Feedback" promoted from `draft` to `active`. Its Rationale was corrected (the mark-less empty state was already satisfied by the existing "No marks available" message, not unimplemented), and its zero-result acceptance criterion now states where the message appears and how the state is reachable: because marks are derived from the current playlist and filtering uses OR logic, selecting a mark always matches at least one track, so zero results only occur when playlist contents change while a filter stays active.
- `src/views/Playlist.vue`: added a `No tracks match the selected filters` empty state rendered in place of the virtual list when filters are active and match no tracks; added an `X/Y tracks` count next to the playlist title while at least one mark is selected; extracted the repeated "resolve playlist tracks" logic into a single `allTracks` computed shared by `availableMarks`, `filteredTracks`, and the new count, and added `hasActiveFilters` / `hasNoFilterResults` computeds.
