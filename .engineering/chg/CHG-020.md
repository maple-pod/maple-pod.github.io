## Rationale

Physical Android testing isolated per-track `HTMLAudioElement.src` replacement as the practical background-continuity failure boundary: a pre-concatenated long file, a five-track MSE sequence, runtime MSE future replacement, and bounded MSE scheduling all remained continuous while normal source replacement did not. The maintainer therefore requested that the production player be migrated to an MSE-based source architecture from the latest master in a fresh worktree.

## Sources

- Maintainer physical-device results: fixed-source and MSE diagnostics remained continuous and correct in Android background playback, including runtime queue mutation.
- CHG-015 through CHG-017 browser and physical validation of sequence-mode append, future removal/replacement, bounded eviction, navigation, and stable source identity.
- Production browser instrumentation in this worktree: Dragon Dream playback assigned exactly one `blob:` source; Next to Floral Life and a natural boundary into Go Picnic updated Media Session metadata while that same source remained unchanged.
- Production fallback instrumentation: Deep Cave (`m4a`/AAC) remained playable through the direct `/resources/bgm/DeepCave.m4a` source path.

## Changes

- Add a production `useMseAudioPlayback` controller that owns a stable `MediaSource`, sequence-mode `SourceBuffer`, bounded previous/current/future entries, queue reconciliation, local/global timeline mapping, and source lifecycle cleanup.
- Route validated WebM/Opus playback through MSE while retaining direct-source fallback for representations not explicitly enabled for MSE.
- Extend queue state with playback-driven current-track synchronization so natural MSE boundary crossings advance the logical queue without initiating a source replacement.
- Map player seek, progress duration, repeat-one, next/previous, queue navigation, random/reordered future state, normalization gain, and Media Session position to logical track time while the media element clock remains global to the MSE timeline.
- Invalidate stale direct and MSE source work on rapid track changes so a late fallback resolution cannot overwrite a newer stable MSE source.
