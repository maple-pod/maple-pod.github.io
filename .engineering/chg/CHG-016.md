## Rationale

Physical Android testing showed that a five-track MSE sequence can remain continuous in the background while normal per-track `audio.src` replacement stops. Maple Pod queues can change at runtime, so the next diagnostic must prove that already-buffered future tracks can be replaced without changing the authoritative media element or its source identity.

## Sources

- Maintainer physical-device report after `d024959`: the MSE five-track background diagnostic did not interrupt.
- Desktop Chromium POC: an initial sequence A → B → C buffered continuously, removing B/C left A intact, and resetting `SourceBuffer.timestampOffset` to A's end allowed E → D to be appended as the replacement future.
- The same desktop Chromium POC crossed both replacement boundaries A → E and E → D while retaining the exact same `audio.src` blob URL.

## Changes

- Extend `/diagnostics/native-audio-background.html` into an interactive dynamic-queue MSE diagnostic.
- Pre-fetch five WebM/Opus inputs, initially append A → B → C, and expose a user action that removes the unplayed B/C future and appends E → D at A's existing end boundary.
- Keep one `HTMLAudioElement` and one `MediaSource` object URL for the entire test; do not replace `audio.src` and do not configure Media Session.
- Expose Previous, Next, and a jump-to-near-boundary control using timeline seeks so physical testing can exercise navigation without source replacement.
- End the MediaSource after successful mutation so A → E → D can continue in the background without further JavaScript buffer work.

## Verification

Result: passed

- Desktop Chromium POC produced initial buffered range 0–310.283 seconds for A → B → C.
- Removing the unplayed B/C future reduced the buffered range to 0–125.581 seconds without changing A.
- Appending E → D from `timestampOffset = 125.581` produced one continuous 0–375.303-second range representing A → E → D.
- Chromium crossed both A → E and E → D boundaries while playback remained active and `audio.src` stayed byte-for-byte the same blob URL before and after mutation.
- The deployed-page implementation test changed A → B → C into A → E → D while the element remained playing, then naturally crossed A → E from ten seconds before the boundary with the same blob URL.
- Diagnostic Next moved E → D and Previous moved D → E using timeline seeks without changing `audio.src`; the browser console reported 0 errors.
- Physical Android background continuity after runtime future replacement remains intentionally pending the maintainer's deployed-device test.
