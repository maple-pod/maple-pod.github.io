## Rationale

Maple Pod already had a coherent visual identity but lacked an explicit design-system contract, while the player exposed confirmed interaction/accessibility gaps and produced an audible click/pop during track changes. This transaction formalizes the existing visual direction, centralizes reusable interaction rules, and replaces abrupt/debounced source switching with deterministic click-free transitions without introducing musical crossfading.

## Sources

- Maintainer-approved scope and acceptance criteria recorded in GitHub issues #3, #4, and #5.
- Browser-reproduced Space-key interception, player control accessibility gaps, and slider interaction/layout behavior in the incumbent application.
- Maintainer report of a short audible noise during every track switch.

## Changes

- Introduced ADR-007 to formalize `DESIGN.md`, semantic PikaCSS tokens, staged strict-token governance, reusable `Ui*` contracts, and the Maple Memory Player creative direction.
- Introduced REQ-011 for keyboard, accessible-name, focus, touch-target, and reduced-motion interaction requirements.
- Introduced REQ-012 for click-free track switching, last-request-wins source resolution, Blob URL ownership, and preserved volume/mute behavior.
- Added `UiIconButton`, corrected global Space shortcut handling, standardized player control accessibility semantics, and expanded primary player/slider hit areas without enlarging visual glyphs or slider geometry.
- Added semantic design tokens, focus/motion primitives, reduced-motion behavior, and removed shared `transition: all` usage.
- Reworked audio source transitions to fade output around source replacement, remove empty-source assignment and fixed debounce behavior, preserve user volume/mute state, and safely release stale/current Blob URLs.
- Added failed-media terminal handling so a rejected source clears waiting and restores output gain, and corrected repeat-all for single-item queues.
- Restructured progress timing labels beside the reserved 44px slider interaction row so the enlarged pointer target no longer overlays labels or escapes the player card; corrected reduced-motion marquee ellipsis behavior.

## Verification

- `pnpm lint` passed.
- `pnpm type-check` passed after PikaCSS preparation.
- `pnpm build` passed with zero PikaCSS strict warnings.
- Browser checks confirmed the Space shortcut no longer steals native interactive-control behavior and player toggle buttons expose stable accessible names with `aria-pressed` state.
- Browser checks confirmed horizontal progress and vertical volume sliders keep 16px visual thumbs while exposing 44px interaction regions; pointer interaction outside the visible 6px rail remains functional and endpoint geometry is preserved.
- Instrumented browser playback confirmed source replacement occurs at zero output, rapid track changes honor the latest request, Blob URLs are released without revoking the active source, and logical volume/mute settings persist.
- Browser playback traces confirmed natural `ended → next`, repeat-one, repeat-all, offline Blob playback, and Media Session next-track behavior continue to work.
- Forced network failure for an audio source confirmed `waiting=false` and actual/logical volume recovery to 0.37, followed by successful playback of a valid track.
- Browser geometry checks confirmed the progress slider root is contained within its dedicated 44px row and the 150px player card on desktop and at a 390px viewport; timestamp hit-testing resolves to the labels rather than the slider.
- Reduced-motion browser checks confirmed marquee containers use `text-overflow: ellipsis` while overflow children become inline with spatial transform disabled.
- A single-item repeat-all handler check confirmed an ended track resets to the start and resumes playback; the multi-item last-to-first repeat-all path remained functional.
