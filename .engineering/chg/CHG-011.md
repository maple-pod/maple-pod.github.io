## Rationale

Physical Android testing after the earlier AudioContext recovery change still reproduced a mid-track stall that resumed immediately when the page returned to the foreground. That result shows playback continuity cannot depend on a running Web Audio context. The media element must remain able to drive native browser/OS output while Web Audio is treated as an optional foreground enhancement.

## Sources

- Maintainer physical-device report: playback stopped mid-track in the background and resumed when foregrounded after CHG-008.
- Chromium browser POC showed `captureStream()` leaves the `HTMLAudioElement` playback clock independent of AudioContext state: with `AudioContext.resume()` forced to no-op and the context held `suspended`, media time advanced from 0.83s to 2.13s and then 2.94s.
- `captureStream()` POC showed captured audio remains non-zero while the media element native `volume` is zero and while the media element is muted.
- Browser POC covered WebM/Opus, M4A/AAC (`DeepCave.m4a`), and Blob-backed M4A playback with non-zero captured audio.
- Chromium source replacement POC showed each `audio.src` replacement adds a new captured audio track; rebinding a new `MediaStreamAudioSourceNode` restores the new source, while stopping/removing stale tracks keeps the stream at one live track.
- Controlled lifecycle POC showed hidden playback stays on native output while AudioContext is held `suspended`, naturally advances Dragon Dream → Floral Life, remains native when foreground resume is blocked, and switches back to enhanced output only after a real resume succeeds.
- Simulated unsupported-browser POC with `captureStream` removed created zero AudioContexts while Dragon Dream → Floral Life natural playback and explicit Next → Go Picnic remained active through the native media element.

## Changes

- Modified ADR-008 so `HTMLAudioElement` is authoritative playback and `captureStream()` feeds an optional Web Audio gain graph without rerouting native media output.
- Modified REQ-003 so hidden/non-running/unsupported states must preserve playback through native media output and foreground recovery is make-before-break.
- Modified REQ-013 so runtime loudness normalization is required only while native-safe Web Audio enhancement is active; native fallback may bypass normalization to preserve continuity.
- Replaced `MediaElementAudioSourceNode` routing with `captureStream()` plus per-source `MediaStreamAudioSourceNode` rebinding while retaining one AudioContext and gain graph.
- Added synchronous native fallback on page hiding and immediate native fallback whenever AudioContext becomes non-running.
- Added guarded foreground recovery that restores enhanced output only after AudioContext is confirmed running and a captured source is bound.
- Added stale captured-track stop/removal so source replacements do not accumulate live MediaStream tracks.
- Added capability fallback that avoids creating AudioContext when `captureStream()` is unavailable.

## Verification

Result: passed

- POC `pnpm lint` passed.
- POC `pnpm type-check` passed.
- POC `pnpm build` and theme verification passed.
- WebM/Opus captured playback, natural source replacement, explicit Next, and gain graph operation passed.
- M4A/AAC direct and Blob playback produced non-zero captured audio at an audible sample point.
- Android Chrome UA POC used enhanced output while visible, switched to native output while hidden, remained active with AudioContext forced `suspended`, and naturally advanced to the next track.
- Simulated no-`captureStream()` environment created zero AudioContexts and retained native initial, natural-next, and explicit-next playback.
- Formal master-checkout Android-UA lifecycle verification confirmed visible enhanced output (`media.volume = 0`), hidden native output (`media.volume = 1`), media time advancing from 0.86s to 1.76s while AudioContext stayed `suspended`, natural transition to Floral Life while still suspended, native output retained when foreground resume was blocked, and enhanced output restored only after a real resume.
- Formal master-checkout source replacement verification retained exactly one live captured track after the hidden Dragon Dream → Floral Life transition.
- Formal master-checkout simulated no-`captureStream()` verification created zero AudioContexts and retained native Dragon Dream → Floral Life playback.
- Physical long-duration Android background verification remains required after deployment because desktop browser automation cannot reproduce OS-level process scheduling or vendor battery management.
