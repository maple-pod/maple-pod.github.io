## Rationale

The current player mixes authoritative HTML media-element playback state with Web Audio graph construction, gain processing, fade scheduling, and AudioContext lifecycle recovery in one composable. The planned native/enhanced routing experiments need those output concerns to be replaceable without changing the media element that owns source loading, playback position, and playback state. This change establishes that boundary without changing the active routing strategy or user-visible playback behavior.

## Sources

- Maintainer-approved playback architecture plan: keep `HTMLAudioElement` authoritative and make Web Audio an optional output/enhancement layer in later phases.
- ADR-008 already defines the current Web Audio graph and keeps the HTML media element as the media source, Media Session-facing playback primitive, and fallback path.
- The pre-change implementation in `useAudio.ts` owned media playback state and Web Audio graph/output state together.

## Changes

- Extracted Web Audio graph creation, normalization gain, transition gain, user-volume gain, fade cancellation, AudioContext lifecycle recovery, and output synchronization into `useAudioOutput`.
- Kept media loading, play/pause, timing, loop state, and media-element events in `useAudio` while preserving its public API for existing callers.
- Preserved unload-time fade cancellation explicitly through the new output boundary.
- Clarified ADR-008 that Web Audio output state is isolated from the media element's authoritative playback state; the routing itself remains unchanged in this phase.
