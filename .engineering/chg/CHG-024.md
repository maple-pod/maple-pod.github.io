## Rationale

REQ-015 requires the global Downloads and Settings icon actions to expose accessible tooltips. With Reka UI 2.10.4, nesting `DropdownMenuTrigger` inside the existing `UiTooltip` places the menu anchor under the tooltip's Popper context. The dropdown still opens, but its own Popper root has no anchor and falls back to an off-screen `translate(0px, -200%)` position.

## Sources

- REQ-015 global top-bar action and tooltip requirement.
- Browser reproduction against the current production build, where Settings and Downloads menus opened with off-screen Popper wrappers.
- Controlled browser comparison showing that removing the nested Reka tooltip immediately restored the dropdown anchor and normal menu positioning.
- Installed Reka UI 2.10.4 `TooltipTrigger`, `DropdownMenuTrigger`, `MenuAnchor`, and `PopperAnchor` implementations, which confirm that both trigger primitives register an anchor against the nearest Popper context.

## Changes

- Keep `DropdownMenuTrigger` directly under the dropdown's own Reka tree so its Popper anchor remains bound to the dropdown.
- Render the optional top-bar trigger tooltip as a lightweight sibling anchored to a relative wrapper instead of nesting another Reka Popper around the dropdown trigger.
- Preserve hover and keyboard-focus tooltip behavior on hover-capable input, suppress the tooltip while the menu is open, and retain the existing no-tooltip behavior on touch/non-hover input.

## Verification

Result: passed

- Controlled comparison with the trigger tooltip disabled restored Settings to `x=1016, y=61`, confirming the nested tooltip as the causal condition.
- Production-like preview confirmed Settings tooltip appears below the trigger on hover and Settings dropdown opens at `x=1016, y=61` with a 30px anchor; the tooltip is absent while the menu is open.
- Production-like World Map preview confirmed Downloads tooltip appears below the trigger on hover and Downloads dropdown opens at `x=927, y=61` with a 30px anchor; the tooltip is absent while the menu is open.
