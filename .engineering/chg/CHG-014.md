## Rationale

Physical Android testing still shows background playback interruption after removing Web Audio, `captureStream()`, and native volume-to-zero track transitions. A minimal single-source page is needed to determine whether the interruption persists without Maple Pod player logic, queue changes, source replacement, or custom Media Session state.

## Sources

- Maintainer physical-device report after `4c9cea7`: Android background playback still stops.
- Maintainer physical-device report: both Chrome and Firefox exhibit the background interruption.
- Existing resources contain compatible WebM/Opus 48 kHz stereo tracks that can be concatenated with stream copy into one long diagnostic source.

## Changes

- Add `/diagnostics/native-audio-background.html` as a static HTML page outside the Vue application runtime.
- Use exactly one native `<audio controls>` element and one fixed source URL.
- Use a commit-pinned CDN resource containing Dragon Dream, Floral Life, Go Picnic, Rest N Peace, and Fairy Tale concatenated without audio re-encoding.
- Do not configure Media Session or perform source replacement on the diagnostic page.

## Verification

Result: passed

- The merged diagnostic source probes as WebM/Opus, 48 kHz stereo, 661.825 seconds, and was produced with stream copy.
- The commit-pinned CDN audio URL returns HTTP 200 with `video/webm` and range support.
- The diagnostic HTML contains one `<audio>` element, one fixed source URL, and zero `<script>` elements.
- The production build copies the diagnostic HTML into `dist/diagnostics/` without adding application scripts.
- Physical Android long-running background behavior remains intentionally unverified until the maintainer tests the deployed diagnostic page.
