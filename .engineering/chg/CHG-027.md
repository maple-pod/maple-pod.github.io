## Rationale

The first REQ-017 implementation incorrectly interpreted contain-fit as also imposing a native-image-size ceiling. That kept large desktop World Maps near their source pixel dimensions even when the focused map section had substantially more usable width and height, leaving unnecessary empty space. The intended behavior is standard maximal `contain`: preserve the published aspect ratio, allow upscaling or downscaling, and grow until either the available width or available height becomes the limiting dimension.

## Sources

- Maintainer feedback from production showing the desktop map remained much smaller than the available focused map section.
- `REQ-017` — contained World Map artwork and deterministic spot interaction.
- `CHG-026` — initial contain-fit implementation whose native-size ceiling is corrected here.

## Changes

- Updated `REQ-017` to define maximal contain-fit explicitly: no native-size ceiling, both width and height constraints apply, and non-zero layouts must reach one limiting dimension while preserving aspect ratio.
- Removed the native-width and native-height caps from `src/views/WorldMap.vue`; the rendered map width is now limited only by the map section width and the width implied by its available height through the published aspect ratio.
- Preserved the existing structured-link-only navigation boundary, deterministic dense-spot arbitration, semantic keyboard controls, and popover presentation behavior.
