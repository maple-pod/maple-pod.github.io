## Rationale

Physical Android testing of CHG-011 showed two failures on the capture/Web Audio enhancement path: foreground audio became intermittent, and background playback still stopped. A native-only Android build is required to isolate whether browser-native `HTMLAudioElement` playback itself remains continuous without any capture or AudioContext dependency.

## Sources

- Maintainer physical-device report after `5a10a63`: foreground capture playback is intermittent.
- Maintainer physical-device report after `5a10a63`: background playback still stops.
- Chromium Android enables muted-background-audio suspension behavior, increasing the value of an uncontaminated native-media baseline.

## Changes

- Bypass the capture/Web Audio enhancement capability on Android user agents.
- Keep the existing hybrid enhancement unchanged on non-Android supported browsers.
- Record Android native-only playback as a diagnostic reliability baseline in ADR-008, REQ-003, and REQ-013.

## Verification

Result: passed

- `pnpm lint` passed.
- `pnpm type-check` passed.
- `pnpm build` passed, including theme verification.
- EF snapshot validation passed with 0 errors, 0 warnings, and 0 info diagnostics.
- Android-UA browser instrumentation observed 0 `captureStream()` calls and 0 `AudioContext` constructions while native playback and explicit source replacement continued.
- Desktop-Chromium instrumentation still observed the capture/Web Audio enhancement path, confirming the diagnostic gate is Android-specific.
- Physical Android long-running background continuity is intentionally left to the deployed A/B test; this change establishes the uncontaminated native-only baseline rather than claiming that result in advance.
