## Rationale

Physical Android testing of the native-only baseline showed that foreground playback is stable but background playback still stops. The maintainer also observed that the browser media notification disappears during a track switch and then reappears for the replacement track. In native-only mode the existing 30 ms transition envelope is implemented by driving the authoritative `HTMLAudioElement.volume` to zero before replacing `src`, unlike the earlier Web Audio path where the media element itself remained audibly active while a GainNode faded the output. This change isolates that variable before evaluating a more complex multi-element design.

## Sources

- Maintainer physical-device report on Android: pure native foreground playback is stable, but background playback still stops.
- Maintainer physical-device observation: the media notification disappears during each track switch and then reappears.
- Current implementation inspection: the Android native-only path applies the source-switch envelope through `HTMLAudioElement.volume`, reaching zero before `src` replacement.

## Changes

- Bypass the track-switch transition envelope while the Android native-only diagnostic baseline is active.
- Keep the authoritative media element at the user's logical native volume across source replacement, except for the user's own mute/zero-volume preference.
- Keep the existing transition envelope unchanged on non-Android enhanced playback.
- Record the diagnostic exception in ADR-008, REQ-003, and REQ-012.

## Verification

Result: passed

- `pnpm lint` passed.
- `pnpm type-check` passed.
- `pnpm build` passed, including theme verification.
- Android-UA browser instrumentation observed 0 `AudioContext` constructions and 0 `captureStream()` calls.
- Android-UA natural source replacement produced no transition-driven `HTMLMediaElement.volume` writes; the replacement track `play()` request occurred with native volume still at the user's logical value in the test.
- Desktop-Chromium instrumentation still used one capture/Web Audio graph and retained the existing enhanced-output transition behavior.
- Physical Android media-notification continuity and long-running background playback remain real-device follow-up checks; this change does not claim those outcomes in advance.
