## Rationale

The resources pipeline now publishes multiple selectable GMS/TWMS World Map snapshots behind a catalog and versioned v3/v8 runtime. The UI must adopt that contract without allowing node caches, in-flight work, pointer hit areas, route state, or offline readiness from one snapshot to affect another.

## Sources

- Maintainer-provided World Map UI migration handoff defining the catalog, versioned runtime, routing, interaction, cache, offline, and acceptance requirements.
- `maple-pod/resources/output/world-map/` production output, including all 13 selectable snapshot manifests/chunks and published `hitPath` geometry.
- Existing ADR-009 and REQ-014 progressive World Map contract.

## Changes

- Introduce and activate REQ-016 for catalog-selected versioned World Map snapshots, snapshot query routing, cross-snapshot isolation, exact `hitPath` pointer geometry, and snapshot-aware offline readiness.
- Update REQ-014 so progressive loading is scoped to the catalog-selected snapshot rather than the legacy unversioned GMS/270 manifest.
- Update ADR-009 to select the catalog plus versioned schema-v3/canonical-v8 runtime as the formal UI contract and relegate the unversioned schema-v1/canonical-v6 alias to resources-side compatibility only.
- Update the frontend runtime schemas, loading/caching composables, offline manager, service-worker runtime-cache patterns, route synchronization, snapshot selector, and SVG/HTML interaction split to implement the versioned contract, including independent multi-snapshot offline retention, revision-keyed manifest/node/image cache identities, per-snapshot cross-tab mutation serialization, per-snapshot revision pruning by manifest `cacheKey`, and forward-safe runtime/canonical schema-generation cleanup that removes known older generations without deleting future ones.

## Verification

Result: passed

- Parsed the production catalog and all 920 chunks across all 13 selectable snapshots through the frontend strict schemas successfully.
- `pnpm lint` passed.
- `pnpm type-check` passed.
- `pnpm build` passed, including PWA generation and theme-token verification.
- `git diff --check` passed.
- Browser smoke testing loaded GMS/270, TWMS/124 archived-WZ, and TWMS/236 MapleStory.IO paths with no console errors; GMS/270 to TWMS/236 requested the versioned TWMS manifest/chunk instead of reusing the GMS node.
- Browser route testing normalized an invalid snapshot query to the catalog default GMS/270 and restored valid snapshot identity in the URL.
- Browser interaction testing confirmed published SVG `hitPath` hover/click navigation, visible negative-coordinate overflow support, semantic HTML link controls with Tab focus plus Enter/Space activation, and `hitPath: null` rectangular fallback controls.
- Browser offline testing downloaded GMS/270 and TWMS/236 simultaneously into independent retained entries: 107 + 96 node chunks and 201 + 173 images remained cached together, and the global Downloads menu restored both entries after reloading outside the World Map route.
- Browser cache-lifecycle testing injected an older `cacheKey` revision for GMS/270 and confirmed only that stale GMS revision was pruned while TWMS/236 remained intact; injected legacy/unversioned and older runtime-contract cache namespaces and metadata were removed on reload while both current v3/canonical-v8 snapshot downloads remained intact.
- Browser integrity testing removed a cached TWMS/236 node after marking the snapshot ready; direct reload downgraded only TWMS/236 to downloadable/partial, removed its incomplete cache, and preserved GMS/270 ready data. Re-downloading TWMS/236 restored its 96 nodes and 173 images.
- Browser multi-tab testing started GMS/246 and TWMS/253 downloads from two already-open tabs; independent per-snapshot metadata preserved all four downloaded snapshots (GMS/270, GMS/246, TWMS/236, TWMS/253) with 395 total node chunks and 725 total images instead of losing one tab's registry update.
- Browser removal testing removed GMS/270 independently and confirmed TWMS/236 retained its manifest, 96 nodes, 173 images, and ready metadata.
- Browser same-snapshot concurrency testing started TWMS/256 downloads from two already-open tabs simultaneously and converged on one ready revision with exactly 98 nodes and 175 images; removing TWMS/256 from one tab immediately restored the download action in the other tab and removed only TWMS/256 data.
- Browser revision-race testing used an isolated origin that served a valid synthetic K1 manifest to one tab and K2 to another while the K1 offline download was in flight. After K2 was observed, all K1 manifest/node/image entries and K1 ready metadata were absent; only the K2 revision remained, and the K2 tab stayed downloadable until its full offline set was prepared.
- Browser migration testing injected legacy/unversioned, v2/canonical-v7, current-contract legacy aggregate metadata, and a synthetic future v4/canonical-v9 generation. Reload removed the known legacy/older generations while preserving the future cache and metadata untouched.
- Browser offline-reload testing downloaded GMS/93 (22 nodes, 40 images), switched the browser offline, and directly reloaded the World Map route; the catalog and unique revision-keyed manifest restored GMS/93 without network access and retained ready state.
