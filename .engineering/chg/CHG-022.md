## Rationale

After introducing the playback-backend boundary, `useAudio` had exactly one caller: `useHtmlAudioPlaybackBackend`. Keeping both composables made the HTML backend an adapter over an otherwise-unused abstraction, while `useAudioPlaybackBackend` added a second wrapper that always returned the HTML implementation. The maintainer accepted collapsing these layers so the replaceable boundary remains `AudioPlaybackBackend`, not internal web-only helpers.

## Sources

- Maintainer acceptance to inline the single-use `useAudio` implementation into the HTML playback backend.
- Repository reference scan showing `useAudio` was only called by `useHtmlAudioPlaybackBackend`.
- ADR-010, which defines `AudioPlaybackBackend` as the transport boundary intended for a future Cordova/native implementation.

## Changes

- Move the HTML media-element lifecycle, reactive playback state, source loading, readiness handling, and media events directly into `useHtmlAudioPlaybackBackend`.
- Remove the now-unused `useAudio` composable and the redundant `useAudioPlaybackBackend` wrapper; `useAudioPlayer` defaults directly to `useHtmlAudioPlaybackBackend`.
- Keep `useAudioOutput` as a private HTML-backend implementation helper because it still owns the current non-Android Web Audio normalization and output-transition behavior.
- Replace the old `loopupdate` ref-property workaround with direct loop state synchronization inside the HTML backend.
- Update ADR-010 so its documented composition boundary matches the implementation.
