## Rationale

The player uses Web Audio for long-form music playback rather than latency-sensitive interactive audio. Mobile background playback can still be interrupted by browser or operating-system lifecycle policy, but requesting the playback latency category gives the user agent permission to favor sustained, power-efficient playback over minimum interactive latency without changing the audio graph or media source.

## Sources

- Maintainer requested an Android production A/B test after reproducing mid-track background stalls that resume on foreground.
- Web Audio `AudioContextOptions.latencyHint` defines `playback` as the category for sustained playback where increased latency is acceptable in exchange for reduced power use and longer playback time.
- ADR-008 already records mobile/background AudioContext lifecycle as a compatibility risk, so this change remains a best-effort implementation hint rather than a background-playback guarantee.

## Changes

- Create the Web Audio `AudioContext` with `latencyHint: 'playback'`.
- Keep the existing media-element source, normalization, transition, user-volume graph, and lifecycle recovery behavior unchanged.
