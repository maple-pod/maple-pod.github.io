## Context

The product is a free fan-made music player. It needs cheap, reliable hosting and access to a sizable audio catalog, but no per-user server state (PRD-003 keeps user data on the device).

## Decision

Run the whole application as a static single-page app deployed to GitHub Pages via GitHub Actions, with all music data, audio, cover, and background assets served from the external host `https://maple-pod.deviltea.me` (proxied as `/resources/*` by the Vite dev server during development).

## Alternatives

Not recorded at adoption time; this decision predates EF adoption and no contemporaneous comparison of hosting/backend options survives.

## Consequences

- Zero server cost and no backend to operate; deploys are a static upload on push to `master`.
- All personalization must live client-side (REQ-006) and sharing must be URL-based (ADR-006).
- The app depends on the availability of the external resource host for audio and images.
- Client-side routing requires the GitHub Pages `404.html` fallback (REQ-009).
