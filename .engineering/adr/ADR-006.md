## Context

Sharing playlists and migrating user data between devices (PRD-004) must work without any server-side storage (ADR-001).

## Decision

Encode shareable payloads as typed "hash actions" in the URL fragment — `import-saveable-playlist` and `import-saved-user-data` — handled by dedicated routes (`/import-playlist`, `/setup`) whose middleware parses and validates the payload against valibot schemas before applying it; direct playback links use `/play?musicId=...` with an explicit confirmation dialog.

## Alternatives

Not recorded at adoption time; this design predates EF adoption.

## Consequences

- Any playlist or setup link is self-contained; nothing is stored outside the URL and the receiving device.
- Payload size is bounded by practical URL length limits.
- Every new shareable type needs a valibot schema and a route middleware; validation is mandatory at the boundary (REQ-007).
