## Context

A Vue 3 SPA needs shared state for the music catalog, playback, and user data, plus a safe way to accept persisted and imported data of unknown shape.

## Decision

Keep domain state in Pinia stores (e.g. `useMusicStore`) and cross-cutting logic in shared composables (`useSavedUserData`, `useAudioPlayer`, `useAudioQueue`, ...), with VueUse utilities for persistence primitives. Data entering from storage or URLs is validated with valibot schemas defined in `src/schemas/` before use.

## Alternatives

Not recorded at adoption time; this stack predates EF adoption.

## Consequences

- State logic is testable and auto-imported (unplugin-auto-import) without manual wiring.
- Schema validation at the boundary keeps malformed imports from corrupting saved data (REQ-006, REQ-007).
- Contributors must follow the store/composable split rather than introducing ad-hoc globals.
