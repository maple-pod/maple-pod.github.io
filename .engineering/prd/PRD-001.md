## Problem

Playlists can contain many tracks, and the only way to locate specific ones is to scroll through the entire list. Each track carries a `mark` field (from the ResourceBgm data), but the playlist view offers no way to use it for narrowing the list.

## User Need

Users listening to a playlist want to see only the tracks matching one or more marks they care about, without losing the full list or leaving the playlist view.

## Desired Outcome

The playlist view offers a mark filter: a toggle button opens a dropdown listing every unique mark in the current playlist, users select any number of marks, and the track list narrows to tracks matching any selected mark. Clearing the selection (or navigating away) restores the full list.

## Success Criteria

- Users can open the filter from the playlist header and select multiple marks via checkboxes.
- The track list updates reactively to show exactly the tracks whose mark matches any selected mark (OR logic).
- With no marks selected, all tracks are shown.
- Filter state resets when the user navigates away from the playlist.

## Non-goals

- Persisting filter state across page reloads or navigation.
- AND logic or multi-criteria filtering (marks only).
- Sorting marks by frequency or alphabetically; extraction order is preserved.
- Handling empty/null marks; the data is expected not to contain them.
