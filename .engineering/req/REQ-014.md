## Requirement

The World Map must use the catalog-selected versioned runtime manifest and each manifest node's `chunk` path to browse one runtime node per native `worldMapId`. Normal entry and navigation must not fetch or parse the canonical full `world-maps.json` document. Loaded nodes may remain cached in memory only within their snapshot/runtime identity. Unloaded roots and breadcrumbs may use manifest `canonicalLabel` or `worldMapName`; loaded chunks provide localized names. Links must navigate to listed nodes, spots must preserve selection, and a spot's `selection.trackId` must remain playable through the music player.

The versioned snapshot selection, route identity, cache isolation, exact link hit geometry, and snapshot-aware offline-readiness rules are defined by REQ-016.

## Rationale

The runtime contract replaces the large canonical document with progressive resources so the initial World Map experience remains responsive while retaining the accepted browsing and playback behavior across multiple catalog-selected snapshots.

## Acceptance Criteria

- Initial World Map entry requests the catalog, the selected snapshot manifest, the active node chunk, and that node's referenced images, with no request for `world-maps.json`.
- Navigating to a child or linked node requests only that snapshot's node lazily, and revisiting an already loaded node may use the in-memory cache for the same snapshot/runtime identity.
- Localized labels, breadcrumbs, links, spot selection, and spot `selection.trackId` playback remain available.
- World Map controls retain explicit accessible names, keyboard focus treatment, and the product's established interaction baseline.
