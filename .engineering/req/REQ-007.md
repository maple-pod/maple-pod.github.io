## Requirement

Sharing works entirely through URLs. The app supports: `/import-playlist` links carrying an `import-saveable-playlist` action in the URL hash, `/setup` links carrying an `import-saved-user-data` action, and `/play?musicId=...` direct-play links. Hash payloads are parsed and validated against their valibot schemas (`HashActionImportSaveablePlaylistSchema`, `HashActionImportSavedUserDataSchema`) before anything is imported; direct-play links show a confirmation dialog naming the track before playback starts.

## Rationale

URL-encoded payloads are the only transport that needs no backend (ADR-006); validation and explicit confirmation keep untrusted links from silently altering local data or autoplaying content.

## Acceptance Criteria

- A valid import-playlist link imports the shared playlist; an invalid or malformed payload is rejected without changing local data.
- A valid setup link imports saved user data and then routes to the app root.
- A direct-play link asks for confirmation ("Play Music From Link") and plays only when the user agrees; unknown `musicId` values route to the root view.
- Users can produce share links from the UI (copy-link actions).
