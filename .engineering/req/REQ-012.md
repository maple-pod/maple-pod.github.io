## Requirement

Changing tracks must not introduce a player-generated audible click or pop. Where the active playback backend can apply a transition without making its authoritative native playback path temporarily inaudible, the player must transition output to silence before replacing an actively playing source and restore output after the requested source becomes playable, using only a short transition envelope that is not perceptible as musical crossfading between songs. The Android native-only web baseline bypasses that transition envelope so direct source replacement does not intentionally set native media output to zero.

Transition gain is separate from the user's persisted volume and mute settings. Source replacement must use correct detach/load semantics rather than assigning an empty `src`. Asynchronous source resolution must follow last-request-wins semantics so a stale request cannot replace a newer track selection or invalidate resources owned by the current source. A failed media source must terminate the transition without leaving the player stuck waiting or leaving output gain at silence. A fixed source-change debounce must not be used as a substitute for concurrency control. Transport-specific readiness and source changes remain behind the playback-backend contract.

## Rationale

Direct source replacement can create a discontinuity in an active audio waveform, while empty-source assignment and debounced asynchronous resolution create independent loading and ordering risks. A short output envelope removes the discontinuity where the backend can safely provide it, and explicit request ordering makes rapid navigation deterministic without coupling queue logic to a specific transport.

## Acceptance Criteria

- Manual next and previous transitions do not produce a player-generated audible click or pop during normal enhanced web playback; the Android native-only web baseline may prioritize continuous media-session audibility over the transition envelope.
- Natural `ended → next`, shuffle, repeat-all, and repeat-one behavior continue to follow the queue/repeat contracts, including repeat-all for a single playable queue item.
- The transition does not create a perceptible song-to-song crossfade.
- Rapid track changes leave the most recently requested track as the active source; stale asynchronous source resolutions are ignored, and releasable stale source resources are cleaned up without invalidating the current source.
- User volume and mute persistence are unchanged and are not overwritten by transition gain.
- A failed media load exits the waiting state and restores transition gain so a later valid track can play at the user's logical volume.
- Offline/blob playback and Media Session actions continue to work.
- The web backend's source replacement does not use `src = ''` as the detach mechanism and does not rely on the previous fixed 300 ms debounce.
- Queue and player-state code does not require direct access to the concrete media transport to implement source-transition ordering.
