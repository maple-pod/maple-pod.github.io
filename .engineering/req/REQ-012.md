## Requirement

Changing tracks must not introduce a player-generated audible click or pop. Natural transitions between validated MSE-compatible tracks must remain on one continuous media timeline and do not require source replacement or a song-to-song crossfade. Explicit MSE navigation may use a short output transition around the timeline seek where the output path can do so without making the authoritative native media element temporarily inaudible. Direct-source fallback transitions retain the existing short source-switch envelope where supported; Android native output does not intentionally drive the authoritative media element volume to zero.

Transition gain is separate from the user's persisted volume and mute settings. Any compatibility-fallback source replacement must use correct media detach/load semantics rather than assigning an empty `src`. MSE-compatible queue changes must reconcile buffered timeline entries instead of replacing `src`. Asynchronous source resolution must follow last-request-wins semantics so a stale request cannot replace a newer track selection or invalidate resources owned by the current source. A failed media source must terminate the transition without leaving the player stuck waiting or leaving output gain at silence. A fixed source-change debounce must not be used as a substitute for concurrency control.

## Rationale

Direct source replacement can create a discontinuity in an active audio waveform, while empty-source assignment and debounced asynchronous resolution create independent loading and ordering risks. A short output envelope removes the discontinuity without changing the intended listening experience, and explicit request ordering makes rapid navigation deterministic.

## Acceptance Criteria

- Natural MSE track boundaries remain continuous without source replacement; manual next and previous use timeline seeks and do not produce a player-generated audible click or pop during normal enhanced playback. Android native playback prioritizes media-session continuity and does not intentionally fade the media element itself to zero.
- Natural `ended → next`, shuffle, repeat-all, and repeat-one behavior continue to follow the queue/repeat contracts, including repeat-all for a single playable queue item.
- The transition does not create a perceptible song-to-song crossfade.
- Rapid track changes leave the most recently requested track as the active source; stale asynchronous source resolutions are ignored, and releasable stale source resources are cleaned up without invalidating the current source.
- User volume and mute persistence are unchanged and are not overwritten by transition gain.
- A failed media load exits the waiting state and restores transition gain so a later valid track can play at the user's logical volume.
- Offline/blob playback and Media Session actions continue to work.
- Source replacement does not use `src = ''` as the detach mechanism and does not rely on the previous fixed 300 ms debounce.
