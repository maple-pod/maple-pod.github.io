## Requirement

For a track with valid measured loudness metadata, the player must automatically apply one static per-track gain in the browser using a target of -16 LUFS and a -1 dBTP true-peak ceiling:

`appliedGainDb = min(-16 - integratedLufs, -1 - truePeakDbtp)`

Normalization is part of the default playback behavior and has no user-facing enable/disable preference. Normalization gain remains separate from the user's volume, mute state, and the short transition envelope used for click-free source changes. The source audio representation, stable music ID, queue behavior, offline source selection, and seek position are unchanged. The player does not add a limiter, compressor, EQ, remux, or re-encode step.

Loudness metadata may load after the primary catalogue data. Tracks without valid loudness metadata, a stale or mismatched analysis report, or browsers where the Web Audio graph cannot be established must remain playable with normalization bypassed rather than becoming unavailable.

## Rationale

The source-preserved catalogue spans many production eras and has a wide measured loudness range. Full-catalogue analysis and production use showed that static metadata-derived gain materially improves track-to-track level consistency, while routing playback through the gain graph also substantially reduces audible discontinuity during track changes. The behavior is therefore promoted from an opt-in experiment to the normal playback path.

## Acceptance Criteria

- Loudness normalization has no Experimental setting or persisted user preference and is applied automatically whenever valid metadata and the Web Audio graph are available.
- Existing saved data and imports that contain the retired experimental preference remain valid; that legacy value does not disable the default behavior.
- A track with loudness metadata receives the gain computed by the -16 LUFS / -1 dBTP formula, including gains above unity when peak-safe.
- User volume and mute remain independent of normalization and continue to behave according to REQ-003.
- The click-free transition envelope remains independent of normalization and continues to satisfy REQ-012 during source changes.
- Offline/blob playback and online playback use the same normalization metadata for the same stable music ID.
- Missing or invalid normalization metadata, a report that does not match the current resource build, or unavailable Web Audio support degrades to bypassed normalization and normal media-element playback rather than failed playback.
- Representative browser verification covers loud, quiet, peak-limited, WebM/Opus, and M4A/AAC tracks.
