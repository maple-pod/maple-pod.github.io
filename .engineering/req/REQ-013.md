## Requirement

The player must expose an experimental `Loudness Normalization` setting. The setting is off by default and persists with the user's other preferences. When enabled for a track with measured loudness metadata, the player applies one static per-track gain in the browser using a target of -16 LUFS and a -1 dBTP true-peak ceiling:

`appliedGainDb = min(-16 - integratedLufs, -1 - truePeakDbtp)`

Normalization gain is separate from the user's volume, mute state, and the short transition envelope used for click-free source changes. The source audio representation, stable music ID, queue behavior, offline source selection, and seek position are not changed by toggling normalization. This experimental version does not add a limiter, compressor, EQ, remux, or re-encode step.

Loudness metadata may be loaded lazily when the feature is enabled. Tracks without valid loudness metadata, a stale/mismatched analysis report, or browsers where the required Web Audio graph cannot be established must play with normalization bypassed rather than becoming unavailable.

## Rationale

The source-preserved catalogue spans many production eras and has a wide measured loudness range. A static metadata-derived gain can reduce track-to-track level jumps without altering the audio assets. Shipping it behind a clearly labeled experimental setting lets willing listeners use it in normal playback while preserving an immediate fallback to the existing sound.

## Acceptance Criteria

- The setting is visible under an Experimental section in Settings, defaults to off, and persists across reloads.
- Existing saved data and imports that predate this preference remain valid and resolve the setting to off.
- With the setting disabled, playback level semantics remain equivalent to the existing player and no source audio bytes are modified.
- With the setting enabled, a track with loudness metadata receives the gain computed by the -16 LUFS / -1 dBTP formula, including gains above unity when peak-safe.
- User volume and mute remain independent of normalization and continue to behave according to REQ-003.
- The click-free transition envelope remains independent of normalization and continues to satisfy REQ-012 during source changes.
- Toggling normalization while a track is playing does not reload the source, reset seek position, or change the current queue item.
- Offline/blob playback and online playback use the same normalization metadata for the same stable music ID.
- Missing/invalid normalization metadata, a report that does not match the current resource build, or unavailable Web Audio support degrades to bypassed normalization, not failed playback.
- Representative browser verification covers loud, quiet, peak-limited, WebM/Opus, and M4A/AAC tracks before the experimental feature is published.
