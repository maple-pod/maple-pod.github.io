## Requirement

For a track with valid measured loudness metadata, the player must automatically apply one static per-track gain in the browser using a target of -16 LUFS and a -1 dBTP true-peak ceiling whenever the Web Audio enhancement path is active:

`appliedGainDb = min(-16 - integratedLufs, -1 - truePeakDbtp)`

Normalization has no user-facing enable/disable preference. Normalization gain remains separate from the user's volume, mute state, and the short transition envelope used for click-free source changes. The source audio representation, stable music ID, queue behavior, offline source selection, and seek position are unchanged. The player does not add a limiter, compressor, EQ, remux, or re-encode step.

Loudness metadata may load after the primary catalogue data. Tracks without valid loudness metadata, a stale or mismatched analysis report, browsers where `captureStream()`/Web Audio enhancement cannot be established, or playback states that require native output must remain playable with runtime normalization bypassed rather than becoming unavailable. Android native-only reliability testing intentionally bypasses runtime Web Audio normalization in all visibility states until an Android enhancement path is proven reliable.


## Rationale

The source-preserved catalogue spans many production eras and has a wide measured loudness range. Full-catalogue analysis and production use showed that static metadata-derived gain materially improves track-to-track level consistency, while the gain graph also substantially reduces audible discontinuity during track changes. Mobile background reliability, however, requires the native media path to remain usable independently of AudioContext lifecycle, so continuity takes priority over runtime normalization while fallback is active.

## Acceptance Criteria

- Loudness normalization has no Experimental setting or persisted user preference and is applied automatically whenever valid metadata and the enhanced Web Audio output path are active.
- Existing saved data and imports that contain the retired experimental preference remain valid; that legacy value does not disable the default behavior.
- A track with loudness metadata receives the gain computed by the -16 LUFS / -1 dBTP formula, including gains above unity when peak-safe, while enhanced output is active.
- User volume and mute remain independent of normalization and continue to behave according to REQ-003 across native/enhanced routing.
- The click-free transition envelope remains independent of normalization and continues to satisfy REQ-012 during source changes.
- Offline/blob playback and online playback use the same normalization metadata for the same stable music ID when enhanced output is active.
- Missing or invalid normalization metadata, a report that does not match the current resource build, unavailable capture/Web Audio support, a hidden page, or a non-running AudioContext degrades to bypassed normalization and normal media-element playback rather than failed playback.
- Android native-only baseline playback remains available without runtime normalization and without creating a captured Web Audio graph.
- Returning to a visible page restores normalization only after the captured source exists and AudioContext is confirmed running.
- Representative browser verification covers WebM/Opus, M4A/AAC, Blob/offline sources, capture-capable playback, and a simulated no-`captureStream()` fallback.
