## Requirement

World Map artwork must preserve each published base image's aspect ratio and use maximal contain-fit within the available map area: it may scale above or below its published/native pixel dimensions as needed, must fit both the available width and available height at the same time, and must grow until either the width or height bound is reached. The map must not intrude into the persistent music player area.

World Map spot pointer and touch interaction must not resolve overlapping generated minimum hit areas by DOM order. Published spot geometry takes precedence over generated hit areas; when a spot has no published geometry, pointer and touch input must use deterministic nearest or otherwise stable arbitration. Semantic keyboard controls for the corresponding spots must remain available.

World Map navigation must be derived only from structured runtime link data. Text or artwork baked into a `BaseImg`/base image must not be inferred as a navigable link when the runtime does not publish corresponding structured link data.

## Rationale

The existing World Map runtime and UI requirements define progressive resources, routed navigation, exact link geometry, and the general 44×44 interaction baseline, but do not define how published artwork is contained in the focused layout, how dense spot points are arbitrated when that baseline produces overlapping pointer rectangles, or how to prevent base artwork from becoming an implicit navigation source. This requirement records those boundaries without changing the runtime resource schema or inventing link metadata that the provider did not publish.

## Acceptance Criteria

- Each World Map node preserves the published aspect ratio of its base artwork and fits within the map area's available width and height at the same time.
- World Map artwork uses maximal contain-fit with no native-size ceiling: for non-zero available dimensions, its effective scale is the minimum of the available-width scale and available-height scale, so the rendered artwork reaches at least one limiting dimension (within layout rounding) without exceeding either one.
- World Map artwork may be rendered larger than its published/native pixel dimensions, and its rendered area does not extend into the persistent music player area.
- A spot's published runtime hit geometry, when present, is used for pointer and touch targeting instead of a conflicting synthesized minimum target.
- Pointer or touch input over overlapping synthesized minimum spot targets is resolved by deterministic geometry-aware arbitration rather than DOM order; identical or otherwise inseparable points use a stable documented resolution while semantic keyboard controls remain operable.
- World Map navigation controls and pointer targets are created only from structured runtime link records; base image text or artwork without a corresponding structured link record never creates a navigation action.
