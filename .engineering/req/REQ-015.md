## Requirement

World Map mode must use a focused layout containing the global top bar, World Map UI, and the persistent music player without the queue/history side panel. The World Map entry must be hidden from the global top bar while already in World Map mode. Global top-bar actions use icon-only controls with accessible tooltips, including Downloads and Settings.

Within World Map mode, the page header must follow the established Playlist header pattern: a back control, a root selector, flexible remaining space, and a compact offline-download action shown only while the complete World Map offline package is not ready. The root selector must use a reusable Reka UI-based select component rather than a native HTML select. User-facing root and navigation labels must prefer canonical GMS display names already available in runtime data; this UI change does not own acquisition of missing display-name data.

World Map node navigation must be represented by vue-router state so browser Back and Forward restore the corresponding map node. The visible breadcrumb must include the selected root and must map to actual navigable routes rather than component-only state. Breadcrumb labels use GMS canonical names rather than browser-locale/TWMS preference.

Navigable World Map link images are dormant by default and become fully visible on hover/focus. Hover/focus popover content must close after the pointer and focus leave both the hotspot detection region and the popover itself, while allowing movement between those two regions without premature dismissal. Popover sizing follows its content instead of a fixed width, subject to viewport bounds, and its primary action spans the full available footer width.

## Rationale

World Map is a dedicated spatial browsing mode rather than another playlist-side-panel view. Route-backed navigation makes map traversal compatible with browser history and shareable navigation semantics, while canonical GMS labels and consistent Reka UI primitives prevent internal game-data identifiers and native-control styling from leaking into the product UI. Hover behavior should expose navigation affordances only when relevant and keep transient details predictable.

## Acceptance Criteria

- Global top-bar actions are icon-only with tooltips; Downloads and Settings have tooltips, and the World Map entry is absent while World Map mode is active.
- World Map mode renders without the queue/history column at desktop widths while preserving the global top bar and bottom music player.
- The World Map page header contains a Playlist-style back control, a reusable Reka UI root select, flexible spacer, and an offline-download action only when the full World Map package is not ready.
- Root select and breadcrumbs display canonical GMS labels when currently available in runtime data; filling missing root display labels is outside this UI change.
- The active World Map node is encoded in the route; link navigation, root changes, and breadcrumb navigation push/replace coherent route state, and browser Back/Forward restores prior nodes.
- Breadcrumbs visibly include the root node and every interactive breadcrumb maps to the corresponding World Map route.
- Navigable link artwork has opacity 0 at rest and opacity 1 while its hotspot is hovered or focused.
- A hotspot popover remains open while the pointer/focus is within either its hotspot or its content and closes after leaving both.
- Popover width is content-driven within viewport bounds and its action button occupies the full footer width.
