## Requirement

World Map mode must use a focused layout containing the global top bar, World Map UI, and the persistent music player without the queue/history side panel. The World Map entry must be hidden from the global top bar while already in World Map mode. Global top-bar actions use icon-only controls with accessible tooltips, including World Map, Downloads, and Settings. Those three top-bar actions must share the same lightweight anchored tooltip behavior, keep dropdown triggers bound to their own Reka menu context, and layer their tooltips above the main content surface.

Within World Map mode, the page header must follow the established Playlist header pattern: a back control, a root selector, flexible remaining space, and a compact offline-download action shown only while the complete World Map offline package is not ready. The root selector must use a reusable Reka UI-based select component rather than a native HTML select. When route state does not resolve a valid root or node, the root defaults to the native `WorldMap` root, falling back to the first valid root only when that snapshot does not contain `WorldMap`. User-facing root and navigation labels must prefer canonical GMS display names already available in runtime data; this UI change does not own acquisition of missing display-name data.

World Map node navigation must be represented by vue-router state so browser Back and Forward restore the corresponding map node. The visible breadcrumb must include the selected root and must map to actual navigable routes rather than component-only state. Breadcrumb labels use GMS canonical names rather than browser-locale/TWMS preference.

Navigable World Map link images are dormant by default and become fully visible on hover/focus. Hover/focus popover content must close after the pointer and focus leave both the hotspot detection region and the popover itself, while allowing movement between those two regions without premature dismissal. On hover-capable desktop input, clicking a hotspot directly navigates or plays, so the popover is informational and must not repeat that action as a button. On touch or other non-hover input, hotspot interaction remains two-step: the first tap opens the popover and its explicit blur-glass action performs navigation or playback; tapping anywhere outside the hotspot and popover dismisses the active popover. The popover title is the location name and must not repeat alternate snapshot/locale name rows in its body. Popover sizing follows its content instead of a fixed width, subject to viewport bounds, and the touch/non-hover action spans the full available footer width.

## Rationale

World Map is a dedicated spatial browsing mode rather than another playlist-side-panel view. Route-backed navigation makes map traversal compatible with browser history and shareable navigation semantics, while canonical GMS labels and consistent Reka UI primitives prevent internal game-data identifiers and native-control styling from leaking into the product UI. Hover behavior should expose navigation affordances only when relevant and keep transient details predictable.

## Acceptance Criteria

- Global top-bar actions are icon-only with tooltips; World Map, Downloads, and Settings share the same anchored tooltip behavior, tooltips remain above the main content surface, Downloads and Settings dropdowns remain anchored to their trigger controls, and the World Map entry is absent while World Map mode is active.
- World Map mode renders without the queue/history column at desktop widths while preserving the global top bar and bottom music player.
- The World Map page header contains a Playlist-style back control, a reusable Reka UI root select, flexible spacer, and an offline-download action only when the full World Map package is not ready.
- Root selection defaults to `WorldMap` when no valid route root/node is present, with first-valid-root fallback only for snapshots that lack `WorldMap`; root select and breadcrumbs display canonical GMS labels when currently available in runtime data.
- The active World Map node is encoded in the route; link navigation, root changes, and breadcrumb navigation push/replace coherent route state, and browser Back/Forward restores prior nodes.
- Breadcrumbs visibly include the root node and every interactive breadcrumb maps to the corresponding World Map route.
- Navigable link artwork has opacity 0 at rest and opacity 1 while its hotspot is hovered or focused.
- A hotspot popover remains open while the pointer/focus is within either its hotspot or its content and closes after leaving both; on hover-capable desktop input it has no redundant navigation/playback button because hotspot activation is direct.
- On touch/non-hover input, tapping a hotspot opens its popover without immediately executing the action, its full-width action uses a translucent blur-glass surface, and tapping outside the hotspot/popover dismisses it.
- Popover title supplies the location name without a repeated alternate-locale/version name list, and popover width remains content-driven within viewport bounds.
