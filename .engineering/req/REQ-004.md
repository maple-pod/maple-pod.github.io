## Requirement

Starting playback from a playlist builds a playing queue from that playlist's tracks — in list order, or in shuffled order when random is enabled. The queue is visible to the user, and recently played tracks are recorded and shown as a history list. When compatible playback uses MSE, queue state remains the source of truth: buffered future media is reconciled to queue changes without replacing the authoritative media element source, and natural MSE track-boundary crossings advance the logical queue state.

## Rationale

A visible queue makes shuffle and repeat behavior predictable, and history lets users return to something they just heard.

## Acceptance Criteria

- Playing a playlist replaces the queue with that playlist's tracks; the chosen track starts first.
- With random enabled, the queue order is shuffled; with it disabled, playlist order is used.
- The playing queue can be inspected in the UI.
- On the MSE playback path, shuffle/reorder and explicit queue navigation reconcile bounded future media while preserving the same `HTMLAudioElement`/`MediaSource` source identity.
- Recently played tracks appear in a history list, persisted as part of saved user data (REQ-006).
