## Policy

All dependency changes must go through the supply-chain baseline configured in `pnpm-workspace.yaml`: newly published versions are held back by `minimumReleaseAge` (with an explicit exclude list for first-party `@deviltea/*` packages), `trustPolicy: no-downgrade` rejects provenance downgrades (with reviewed exact-version excludes only), `blockExoticSubdeps` and `strictDepBuilds` stay enabled, and any dependency that needs install/build scripts must be reviewed into `onlyBuiltDependencies` or `ignoredBuiltDependencies` before it may run.

## Scope

Every dependency addition, upgrade, or override in this repository, including devDependencies and transitive overrides. The baseline lives in `pnpm-workspace.yaml`; each setting is commented in-file.

## Rationale

The app is a client-side PWA published to GitHub Pages, so a compromised dependency ships directly to users. Holding back fresh releases, refusing provenance downgrades, and gating build scripts limits exposure to npm supply-chain attacks. Exceptions (e.g. the workbox 7.4.0 pin against an unattested fork prerelease) are documented next to the setting they relax.

## Compliance

- `pnpm-workspace.yaml` keeps `minimumReleaseAge`, `trustPolicy: no-downgrade`, `blockExoticSubdeps`, and `strictDepBuilds` enabled; removals or relaxations require explicit review.
- New entries in `minimumReleaseAgeExclude`, `trustPolicyExclude`, `onlyBuiltDependencies`, or `ignoredBuiltDependencies` are added only after review, with an in-file comment explaining the exception.
- `.github/workflows/security-audit.yml` runs `pnpm audit --audit-level=moderate` weekly and on manual dispatch.
