## Capability
Provide trustworthy offline readiness for an exact world-map snapshot revision.

## Semantics
The snapshot is ready only when its required runtime resources are complete and verified for the selected revision. Preparation has observable progress, cancellation, failure, retry, removal, and ready states; retained partial data is not a partial ready state.

## Rules
- Readiness is matched to the current snapshot revision and its runtime integrity contract.
- A revision or manifest change invalidates readiness from the prior revision.
- Partial or failed preparation remains not-ready.
- Retrying may reuse retained valid data without weakening the ready boundary.

## Edge Cases
Older, incompatible, cancelled, incomplete, or failed snapshot data cannot appear ready. Removing a snapshot clears its product readiness.
