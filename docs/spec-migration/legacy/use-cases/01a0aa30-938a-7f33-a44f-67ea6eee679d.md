## Preconditions
The resource-maintenance environment can acquire the configured music, visual, analysis, and background inputs.

## Main Flow
1. The maintainer requests a current music and visual resource build.
2. The publication process assembles the catalog and its referenced assets and may produce optional loudness data.
3. The process validates the result as a self-consistent bundle.
4. A valid bundle is published for Maple Pod consumers.

## Alternate & Failure Flows
- Missing, inconsistent, or unusable resource inputs block publication.
- Optional loudness data that is absent does not block ordinary resource publication, but invalid data cannot be used for playback compensation.
- Acquisition, conversion, retry, and deployment steps are not part of this interaction.

## Observable Outcomes
Consumers receive a resource bundle whose declared music, visual, and optional analysis content can be resolved consistently, or a publication failure that leaves the invalid bundle unavailable.
