## Preconditions
The browser can provide the application's supported offline shell and update notifications, or can fall back to ordinary web use.

## Main Flow
1. Maple Pod prepares the application shell for supported generic offline reuse.
2. When that capability is ready, Maple Pod shows an offline-ready notice.
3. When a newer application version is available, Maple Pod shows an update-ready notice.
4. The user may dismiss the notice or explicitly choose Reload.
5. Maple Pod applies the update and reloads only after the user chooses Reload.

## Alternate & Failure Flows
- If the browser cannot provide the supported offline/update capability, Maple Pod remains usable as a normal web application.
- Dismissing an update notice leaves the current session running.
- Generic application-shell readiness does not make Music or World Map content ready for their separate offline experiences.

## Observable Outcomes
The user can see generic offline readiness and update availability when supported, retain the current session until choosing Reload, and distinguish shell availability from content-specific offline readiness.
